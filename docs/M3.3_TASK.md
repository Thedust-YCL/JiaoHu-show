# AGENT / ZERO — M3.3 V1.0 正式发布与项目交付

> **主阶段**：M3 · FINALIZATION & RELEASE  
> **子阶段**：M3.3 · RELEASE & HANDOFF  
> **任务性质**：可直接提供给 Codex 的发布准备、生产验证与版本归档任务书

## 2. 发布前质量门禁（硬性）

优先读取并核对：

- `docs/M3_PERFORMANCE_REPORT.md`
- `docs/M3_QUALITY_GATE.md`
- 前序阶段真实测试报告与当前仓库 CI/脚本（如存在）

若文档缺失、结论不明确或证据不足，则按真实结果补齐检查；不得只为生成报告填写 `READY`。

### P0 立即阻断

- 主页面或关键路径无法启动/进入，或生产构建失败。
- 构建器配置或运行历史存在无提示、不可恢复的数据丢失。
- Runtime、权限、引用追溯或 A/B 指标存在严重逻辑错误。
- 核心业务意外依赖后端、真实 LLM/MCP 或远程服务。
- 静态部署资源 404、子路径失效，或主导航无法进入关键页面。
- 代码或构建产物中包含真实密钥/敏感凭据。
- 存在可复现的严重注入/任意代码执行漏洞。

### P1 原则上阻断公开发布

- 六大章节或核心实验中的关键功能不可操作。
- 大范围响应式布局无法完成关键任务。
- WebGL 降级失败导致核心内容不可访问。
- 重要无障碍路径不可用、历史配置迁移失败或关键数据不一致。
- 已知且影响核心流程的性能/内存问题无可靠缓解措施。

### P2 可记录后续修复

- 不影响主流程的小范围排版细节、次要动画瑕疵或低影响提示文案问题。
- 必须记录复现条件、影响范围、风险、临时措施和后续计划。

质量门禁是否通过依证据和影响范围判断；不得为了发布修改 P0/P1 的定义。

## 4. GitHub Pages / 静态部署验证

### 必须先识别实际部署形态

- 用户主页/组织站点的根路径，或项目站点的仓库子路径。
- React Router / Vue Router 或其他路由是否使用 History 模式、Hash 模式，或自定义静态页面路由。
- 构建工具（例如 Vite）是否需要按实际站点设置 `base`。
- 是否已有 GitHub Actions 部署工作流或手工构建上传模式。

### 检查项

- 所有构建产物均为 HTML/CSS/JS、字体、图片、模型、静态 JSON 等可由静态主机直接托管的资源。
- JS/CSS、字体、图片、模型、知识 JSON、演示资料和代码分包的路径在真实 `base` 下正确。
- 深层链接的直接访问/刷新与浏览器前进/后退适配当前部署方式；若 Pages 不具备服务器端 SPA fallback，需采用受控的 Hash 路由或兼容当前方案的静态回退方式，不要假定所有刷新都能成功。
- 不出现对 `localhost`、开发代理、私有校园接口、调试 API 或未授权域名的运行时依赖。
- 预览环境中模拟任务、配置存储、Knowledge Journal、A/B 比较和 Markdown 导出可正常使用。
- 真实静态预览下浏览器控制台无阻断错误，网络请求失败不会导致核心业务不可用。
- 外链参考资料仍为用户主动点击的普通链接，不能暗中用作业务数据来源。
- 必要时检查资源的大小写敏感、相对路径与特殊字符编码。

**如果无法在当前环境访问线上 Pages，不得写“线上验证通过”；应记录为 `NOT RUN`，提供操作步骤、预期现象与用户需要执行的 URL 访问检查。**

## 5. 关键用户旅程端到端验收

必须验证如下完整使用旅程，不允许只通过组件单测宣布功能完整。

### Journey A — 新用户学习

打开入口 → 电影开场/跳过 → Story 第一章 → 概念详情 → Atlas 关联概念 → Lab 实验 → 返回章节 → Knowledge Journal 查看进度。

检查：无强制卡关；进度源自真实事件；刷新恢复；无 WebGL 时仍可学习。

### Journey B — 构建 Agent

进入 Constructor → 点击/拖拽模块 → Inspector 修改参数 → 2D/3D 同步 → Preflight 发现错误 → 修正 → 保存配置 → 刷新并重新加载。

检查：统一配置来源、真实依赖检查、存储隔离和旧配置迁移。

### Journey C — 模拟执行

读取配置 → 选择场景 → Run/Step → Pause/Resume → 工具失败/重试 → 权限审批/拒绝 → 证据分析 → 结束并检查事件详情。

检查：事件与状态一致；不越权；最终摘要可追溯；同配置/场景/种子可重现。

### Journey D — A/B 对比

选择 A/B 配置 → 相同任务与数据版本 → 双侧运行 → 检查差异 → 查看证据与引用 → 保存实验档案 → 导出 Markdown → 重开历史记录。

检查：比较指标来自实际事件；报告引用存在；历史配置快照不受后续编辑影响。

### Journey E — 异常与降级

WebGL 不可用/上下文丢失、存储异常、无资料、工具失败、权限拒绝、窄屏、减少动画等条件下进行关键操作。

检查：清晰的失败或降级路径，无虚构成功、死循环或无提示清除数据。

## 6. 技术架构、数据隐私与依赖审计

- 浏览器运行时仅使用本地模拟规则、静态演示资料和用户主动产生的本地数据。
- 不存在实际 LLM、Embedding、MCP Server、远程研究工具调用或云端数据库。
- 不存在硬编码密钥、测试凭据、真实个人隐私材料或无意上传的 `.env` 文件。
- 生产构建不暴露不必要的调试数据、开发服务地址或内部测试报告。
- 校验用户输入、渲染外部链接和导入配置的安全边界；避免 `eval`、不必要的 HTML 注入或执行外来代码。
- 确保 Sandbox/Guardrails 是**教学模拟**而非真实生产级安全防护，不作误导宣传。
- localStorage/IndexedDB 中的学习进度、Agent 配置、运行历史与实验档案具备不同命名空间。
- 清除学习记录不得误删运行历史；删除配置不得静默删除既有实验快照。
- 对旧版本数据做兼容验证；若确需迁移，采用非破坏性流程并记录恢复策略。
- 检查依赖许可证及第三方资源版权/使用限制；不把未经许可的字体、媒体或私有素材一并发布。
- 检查核心资产是否需要运行时 CDN；若原 PRD 要求无 CDN 依赖，确保打包方式符合该约束。

## 10. 推荐执行顺序

1. **Audit**：核对仓库、Git 状态、M3.2 质量门禁、部署方式和已知缺陷。
2. **RC Freeze**：明确版本、冻结范围、确认依赖与锁文件。
3. **Build**：在干净安装环境运行类型检查、测试、生产构建与静态资源检查。
4. **Preview**：在生产构建预览中验证路由、子路径、静态资源、浏览器控制台与存储。
5. **E2E**：完成五条关键用户旅程与异常/降级场景。
6. **Security & Data**：检查无远程业务依赖、密钥泄漏、数据隔离、迁移与输入安全。
7. **Docs**：完成 README、用户指南、技术架构、Changelog、Release Notes、Release Checklist、Rollback Plan。
8. **Gate**：逐项执行 A01–A40，形成 `READY_TO_PUBLISH` 或 `BLOCKED`。
9. **Approval Handoff**：向用户列出需要批准的真实发布动作，不擅自执行。
10. **Publish if authorized**：获得明确授权后再发布并线上验收；若工具或权限不支持，则提供真实步骤，不得冒充操作已完成。

### 验收状态规则

- `PASS`：有真实证据支持。
- `FAIL`：实际测试失败。
- `BLOCKED`：受到前置条件阻断。
- `NOT RUN`：尚未运行，或环境不具备执行条件。

未实际访问生产站点时，**线上发布验收必须保留为 `NOT RUN`**，不得将本地预览当作线上成功。

## 13. 最终汇报格式

完成后按以下结构汇报：

1. **版本与仓库状态**：目标版本号、当前分支、未提交变更、是否已推送。
2. **M3.2 门禁**：实际结论、证据、阻断缺陷与修复结果。
3. **构建与部署预演**：真实命令、产物路径、静态资源与 base/path 检查。
4. **五条用户旅程**：实际执行步骤、结果、失败/未执行项。
5. **数据与架构审计**：本地存储、迁移、来源追溯、模拟边界、远程依赖与秘密检查。
6. **文档清单**：更新/新增的文档及其内容。
7. **A01–A40 验收表**：逐项 `PASS/FAIL/BLOCKED/NOT RUN` 和真实证据。
8. **剩余缺陷**：P0/P1/P2，是否阻碍发布。
9. **回滚方案**：实际恢复步骤与数据兼容性风险。
10. **授权交接**：如未授权发布，明确列出下一步需要用户批准的动作，不擅自执行。
11. **最终状态**：`READY_TO_PUBLISH` / `BLOCKED`；如获得授权且已完成线上验证，可为 `PUBLISHED_VERIFIED`。
