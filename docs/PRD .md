# AGENT / ZERO — 产品需求文档（PRD）

> **版本：v0.7｜状态：需求基线冻结｜日期：2026-10-14**  
> 产品定位：AI 智能体交互式知识实验室（An Interactive Atlas of Agentic AI）  
> 品牌主张：**FROM LANGUAGE TO ACTION. / 从语言，到行动。**  
> 本文汇总并保留 PRD v0.1–v0.7 已确认的需求。除发现客观冲突或原型验收不通过，停止常规需求访谈。

## 0. 文档约定与决策优先级

- **P0 不可突破**：100% 浏览器端业务逻辑、无业务后端、无云数据库、无真实 AI API、无账号；生产包可部署到 GitHub Pages 等静态托管；不得把模拟表述为真实模型执行。
- **已冻结的产品方向**：电影化开场 + 控制台探索；黑曜虚空 × 科研终端 × 神经宇宙；分层学习；以 AI 深度研究助手贯穿全站；可配置、多分支、可回放模拟；3D 核心 + 2D 专业控制台；点击自动装配 + 可选引导拖拽；中央核心采用机械轨道 + 黑曜几何核 + 少量神经数据流。
- **设计基线**：本 PRD 定义产品的“做什么/为什么”；`DESIGN_SYSTEM.md` 规定视觉与动效；`M0.1_TASK.md` 只定义首轮高保真原型的“这轮做什么”。冲突时按 P0 → 本 PRD 的产品行为 → 设计规范 → 当前阶段任务处理；若仍存在歧义，记录问题，不自行扩大范围。
- **阶段区分**：M0 是可验证的完整短流程；**M0.1 是 M0 的视觉基础子阶段**。不要把 M0 的完整模拟引擎、研究报告、全部实验当成 M0.1 的交付物。

## 1. 产品概述

### 1.1 一句话定位

AGENT / ZERO 是一座运行在浏览器中的交互式 AI 实验室：用户从一个只能处理语言的模型核心出发，学习指令、上下文、工具、MCP、检索、Skills、记忆、Harness 等概念，通过装配与可视化模拟理解 Agent 何以能够完成多步骤任务。

### 1.2 核心目标

1. **视觉吸引**：电影式入场、可旋转 3D 核心、精密的科研控制台、空间知识图谱，让网页本身成为高完成度的数字作品。
2. **真正理解**：新手通过“一句话解释 → 动态演示 → 深入拆解 → 关联概念”，理解 Agent 技术体系及各名词的边界。
3. **可操作、可验证**：用户装配的工具、权限、策略真实影响**本地模拟**中的执行路径；能观察、暂停、检查、对比、复现结果。
4. **架构简洁**：没有服务器运行费、AI 调用费、业务 API、账号系统；托管静态资源即可运行。

### 1.3 非目标

- 不是真正调用大模型的 Agent 产品，不支持对任意开放问题开展真实自主研究。
- 不抓取实时互联网资料，不接入第三方真实 MCP 服务或真实工具执行。
- 不制作操作系统式窗口管理、无限自由 3D 节点搭建器或低代码平台。
- 不以签到、等级、排行榜或虚假的“AI 准确率/智商评分”为主要游戏化内容。
- 不把所有概念等同为可插拔插件，不宣称 Agent 必须具备所有模块。

### 1.4 目标用户

- 听过 ChatGPT、Claude、Codex、LLM、Agent、MCP、Skills 等名词但关系不清楚的新手。
- 已有一些 AI 使用经验、想直观看懂工具调用、工作流、上下文工程、运行机制的人。
- 喜欢高视觉密度数字作品和可交互学习体验的访问者。

### 1.5 成功标准（定性优先）

- 用户能分辨模型、Agent、工具、协议、Skills、Memory、RAG、Harness、Workflow 的不同职责。
- 用户能在研究任务中说明“关闭/添加某个能力后，执行轨迹为什么改变”。
- 视觉上即使暂停动画，关键截图也具有辨识度、结构感和较高审美完成度。
- 纯静态部署及无业务网络访问时，所有核心模拟仍可运行。

## 2. 产品体验与信息架构

### 2.1 一个中心、三种视图、一个最终构建器

```text
Boot / INITIALIZE（电影式入场，可跳过）
  └─ Control Hub / 中央系统
       ├─ STORY：六章节引导叙事
       ├─ ATLAS：自由探索 AI 知识星图
       ├─ LAB：与概念关联的实验空间
       └─ CONSTRUCTOR：3D 装配 + 2D Inspector
             └─ EXECUTION：研究模拟 / 事件轨迹 / 报告
```

三个入口复用相同的术语数据、实验组件与研究资料；不得复制维护三套相互矛盾的解释内容。未探索术语可自由访问，Story 仅为推荐路径。

### 2.2 页面清单

| 页面/视图 | 目标 | 主要能力 | 阶段 |
|---|---|---|---|
| Boot | 建立电影感、系统唤醒 | 五镜头开场、Skip、Replay、减少动态效果 | M0.1 |
| Control Hub | 全站导航中心 | 3D 核心、章节入口、系统状态、研究任务入口 | M0.1 起 |
| Story | 建立连贯认知 | 六章节、滚动叙事、章节间能力演化 | M3 |
| Atlas | 自由查阅技术概念 | 节点、关系、缩放、搜索、聚焦 | M0.3 小样；M3 全量 |
| Knowledge Node | 分层学习 | Understand / Inspect、示例、误解与关联 | M0.3 小样；M3 全量 |
| Laboratory | 亲手观察技术机制 | 参数调整、模拟、失败分支、反馈 | M0.3 起；M3 全量 |
| Constructor | 组装研究能力 | 点击装配、拖拽、参数、权限、双视图 | M0.2 起 |
| Execution Trace | 查看系统做了什么 | 暂停、逐事件回放、数据与来源溯源 | M0.3 起 |
| Report | 看研究结果及局限 | 引用、结论、未核实事项、导出 | M0.4 起 |

### 2.3 主导航约束

- 全站保留返回 Hub、当前路径、返回上一个上下文的明确操作。
- Story / Atlas / Lab 可以互相跳转至**同一知识节点**，选中概念可跳至对应实验或在 Constructor 中定位相关部件。
- 尚未开发的入口在阶段性原型中必须显示“未开放”或不可交互；**禁止假按钮**。
- 导航、文本、输入应为 HTML 语义化元素；Three.js 负责场景而非所有文字。

## 3. 贯穿任务：Deep Research Agent

### 3.1 研究任务（虚构教学案例）

**MISSION 001 — 分散的校园活动信息，值得用 AI Agent 来整合吗？**

设定为一所**虚构大学**，活动公告散落在多个渠道。任务是比较传统规则自动化、LLM 工作流与具有动态决策的 Agent 式流程，输出一份包含证据、局限、方案差异及风险的可行性研究报告。

- 所有活动公告、日期和模拟结果都标注为**虚构教学资料**。
- 公开的技术概念说明可以使用经核实的官方/权威文档，需将“事实性技术资料”与“虚构案例资料”区分。
- 结论**可以是不需要 Agent**：简单而稳定的任务可能更适合传统自动化或固定工作流。
- 首版仅一个完整研究包；后续任务包扩展不改变纯前端技术边界。

### 3.2 数据包目标（M0 完整闭环后的扩展规模）

| 数据类型 | 规模参考 | 用途 |
|---|---:|---|
| 核心研究问题 | 1 | 统一学习叙事 |
| 虚构校园公告 | 8–12 | 搜索、阅读、匹配 |
| 技术比较资料 | 4–6 | 架构分析 |
| 更正/冲突组 | 2–3 | 来源核验 |
| 故障情境 | 4 种 | 工具错误、缺失等 |
| 不可信/恶意指令样本 | 2 种 | 注入与权限边界 |
| 参考研究结论 | 1 套 | 测试与评估 |

示例元数据：`id`、`title`、`source`、`publishedAt`、`content`、`chunks`、`isFictional`、`supersedes`、`tags`。事实引用通过 sourceId/chunkId 路径定位。

### 3.3 标志性冲突

初始虚构公告日期为 10 月 18 日；后续明确更正为 10 月 20 日。研究流程应该检查公告的**发布关系、有效性和更正说明**，不能仅凭“活动日期更晚”武断认定正确。如果无法证实，更合适的是保留冲突并标注不确定性。

## 4. 六章知识体系（分层学习）

| 编号 | 世界/章节 | 名词范围（拟定） | 贯穿问题 | 核心交互 |
|---|---|---|---|---|
| 01 | INTELLIGENCE / 智能诞生 | AI、ML、LLM、Transformer、Token、Inference | 模型为什么能回答，却不一定拥有可验证的外部事实？ | Token/生成示意 |
| 02 | CONTEXT / 指令与上下文 | Prompt、Instructions、System Prompt、Context Window、Context Engineering、Hallucination | 同一个模型为什么表现不同？ | 任务指令、上下文预算 |
| 03 | CONNECTION / 外部能力 | API、Tool Calling、Function Calling、MCP、MCP Server | AI 如何读取外部资料？ | 工具直连与 MCP 连接演示 |
| 04 | KNOWLEDGE / 信息与方法 | Retrieval、RAG、Embedding、Memory、Skills | 信息怎样被检索、引入上下文、保留、复用？ | 文档片段检索、Skill 加载 |
| 05 | RUNTIME / 执行系统 | Agent、Agent Loop、Workflow、Harness、Orchestration、Multi-Agent | 多步骤任务如何规划、执行、检验与调整？ | Workflow/Agent 分支比较 |
| 06 | RELIABILITY / 可靠性与边界 | Permissions、Sandbox、Prompt Injection、Guardrails、Tracing、Evals | AI 系统的结果怎样验证、权限怎样控制？ | 冲突判断、审批、来源追溯 |

目标约 30–40 个高质量概念节点，具体词表在内容审校阶段冻结，不追求无限数量。每个节点包含：一句话解释、可操作示例、深入机制、常见误解、相关概念和参考来源。

**必守技术边界**：

- LLM ≠ Agent；Agent 是围绕模型与运行环境形成的执行系统，不是模型自身的另一种名称。
- Tools 不一定通过 MCP 提供；MCP 是一种标准化连接协议，不等于独立的模型或 Agent，也不保证能力提高。
- Skills 是按需加载的任务说明与可能的资源，不能等同于 API、工具或自动获得网络权限。
- Retrieval、RAG、Embedding、Memory 之间有关联但不是同义词；关键词检索不能冒充向量检索。
- Workflow 与 Agent 的执行控制方式不同，不应强行宣称后者总是更好。
- Harness 表达运行环境、Agent Loop、工具协调与控制等，不能当作一个发光的第二模型。

## 5. 全站核心交互

### 5.1 分层知识体验

每个节点按 Discover → Understand → Experiment → Connect 呈现，并提供：

- **UNDERSTAND**：普通语言解释，尽量少术语。
- **INSPECT**：协议、结构、运行机制、示例数据与误区；示例 JSON 明确标注为简化格式。
- 学习进度状态：未探索 / 探索中 / 完成核心实验 / 发现关联；状态不是知识掌握程度评分。
- Knowledge Journal：浏览器端保存学习过的概念、实验与关键发现。

### 5.2 必须具备代表性的实验

- Token Lab：展示真实分词示例或明确标记的近似计数；不伪造 tokenizer 结果。
- Context Lab：修改研究约束、指令与上下文预算，观察预设行为变化。
- Connection Lab：分辨直接函数调用和 MCP Host/Client/Server 的连接路径，含 Tools/Resources/Prompts 解释。
- Knowledge Vault：文档拆块、关键词检索、预计算向量样本、按需加载 `SKILL.md` 与资源。
- Execution Lab：观察计划—调用—返回—核验—重试—报告等事件及不同控制策略。
- Reliability Lab：冲突核验、引用溯源、权限审批、工具失败、外部文档中的提示注入。

所有实验对外均显示 **SIMULATED / 本地教学模拟**，不得暗示真实模型思维链或实时联网研究。

### 5.3 三张图，三套语义

| 图 | 代表 | 是否随配置改变 |
|---|---|---|
| Knowledge Graph | 概念之间的真实语义关联 | 基础关系不因装配改变 |
| System Graph | 当前已配置的 Agent 组成和连接 | 随用户配置同步变化 |
| Execution Graph | 某次实际模拟执行的路径 | 随模拟事件变化 |

Knowledge Graph 关系类型包括 USES、PART_OF、RELATED、CONTRASTS；关系必须有文字解释、方向与可访问图例。不得以随机线条制造虚假依赖。

## 6. Agent Constructor

### 6.1 视觉与布局

- **Assembly View**：中央 AZ-CORE 01（机械轨道 + 黑曜几何核），围绕核心装配能力；左侧模块架、右侧 Inspector；背景保持克制。
- **Inspector View**：明确的 2D 架构关系、参数、工具输入输出、执行信息；共享同一份真实配置。
- 两个视图只是**同一用户配置的两个投影**，不能维护互相独立的业务状态。
- 默认**点击自动装配**，同时支持兼容接口上的**引导拖拽**；键盘和移动端可用无拖拽的等价路径。

### 6.2 逻辑层与能力

| 层次 | 模块 | 行为举例 |
|---|---|---|
| 模型基础 | Model Core | 固定教学模型行为配置，不是真实推理引擎 |
| 指令/上下文 | Instructions, Context | 决定初始研究约束与模拟行为规则 |
| 工具/协议 | Tools, MCP | 决定模拟工具是否可调用及连接路径的展示 |
| 知识增强 | Retrieval, Skills, Memory | 影响资料检索、研究规范与跨轮次上下文 |
| 运行与控制 | Runtime, Permissions, Guardrails | 决定流程、重试、审批及越权拒绝 |

不是所有模块都可选：模型核心是基础；MCP 属于协议演示；工具、检索、记忆、Skills 等按任务决定；权限规则作用于执行环境。

### 6.3 模块操作

添加、预览、配置、检查、禁用、重新启用、移除；所有更改都必须反映至运行配置。点击自动装配流程：SELECT → PREVIEW → ASSEMBLE → CONFIGURE → CONFIRM。引导拖拽仅吸附至兼容端口；非法目标提示原因并回退；Esc 取消；拖拽时暂缓核心自转。

模块逻辑状态：Available、Preview、Attached、Unconfigured、Ready、Disabled、Invalid。Hovered、Focused、Selected、Dragging 为独立 UI 状态；某一次工具调用错误属于**执行事件**而非模块永久故障。

### 6.4 最终用户旅程

选择研究任务 → 添加/配置模块 → 检查权限与依赖 → 运行模拟 → 查看执行轨迹 → 查阅有出处的报告 → 调整配置并重试 → 保存 A/B 配置对比。模块配置应允许保存与恢复，未登录也可在同一浏览器使用。

## 7. 本地研究模拟引擎

### 7.1 核心原则

- **Configuration-driven simulation / Event-driven visualization**：配置、数据包、规则产生事件与研究结果；3D/2D 只订阅这些结果，**不得靠视觉动画反向判断业务状态**。
- 确定性：相同配置 + 同一任务数据版本 + 同一随机种子（若使用）必须产生可复现事件和结果。
- 所有事件可追溯 sourceId、chunkId、ruleId、branchId；引用能定位原资料。
- 事件时间与视觉动画时间分离；调快回放不得漏执行规则。
- 模拟器不能返回与用户操作矛盾的“成功”动画与报告。

### 7.2 运行状态

`IDLE → CONFIG_VALIDATION → PLAN → SOURCE_DISCOVERY → DOCUMENT_READING → EVIDENCE_CHECK → SYNTHESIS → COMPLETED`，在需要时进入 `CONFLICT / ADDITIONAL_RESEARCH`、`MISSING_DATA / PARTIAL_REPORT`、`TOOL_ERROR / RETRY / FALLBACK`、`PERMISSION_REQUIRED / APPROVE / DENY`。非每次都经历全部状态。

### 7.3 必须支持的分支

1. 工具与来源完备：成功研究并形成有出处的结论。
2. 缺少搜索能力：不能凭空模拟已找到来源。
3. 缺少文档读取能力：不能假装已经读取正文。
4. 来源矛盾：可核验、保留冲突或按策略请求补充研究。
5. 工具错误：按配置尝试重试、降级或停止。
6. 权限不足：操作必须受阻，可请求用户授权（仅模拟）。
7. 外部内容携带越权指令：将其视为不可信内容，不覆盖可信指令或权限。

### 7.4 研究报告

至少包含：任务摘要、主要发现、来源引用、方案对比、证据限制、尚待验证事项。可客户端导出 Markdown/JSON；证据标记可回溯 sourceId/chunkId 与对应执行事件。评估以可计算的**任务完成项、支持的事实条数、引用匹配、冲突处理、步骤/工具调用次数**表示，不伪造“智能 98 分”“准确率 99%”。

### 7.5 Replay

支持播放、暂停、逐事件前进/后退、选中任一事件、0.5×/1×/2×/4× 回放。暂停冻结数据流动态，不妨碍检查静态结果；所有视图显示同一个 eventId 下的状态。支持 A/B 两套配置并排对照，不能断言 Agent 始终胜过 Workflow。

## 8. 视觉与动效约束（摘要）

详见 `DESIGN_SYSTEM.md`。

- 标志：`A/0`；名称：`AGENT / ZERO`；标语：`FROM LANGUAGE TO ACTION.`。
- 配色：Void `#07090D`、Panel `#10151D`、Raised `#17212C`、Signal `#77D8EC`、Attention `#F0BD78`、Verified `#80D9B4`、Error `#FF8585`。
- 字体方向：Inter + Noto Sans SC + JetBrains Mono，打包合规字体子集。
- 核心：黑曜石式几何多面体、三组不同倾角机械轨道、标准化端口、克制的数据脉冲；用结构和光影而非全屏粒子营造科技感。
- 电影式开场约 8–12 秒，默认镜头脚本约 11 秒；可跳过、可重播、首次播放后后续直接进入 Hub；减少动态效果时简化。
- 操作反馈尽量即时；日常微交互约 150–300ms，复杂装配约 400–800ms，章节空间转场约 1–2s，可按实测优化。
- 状态色须有文字或形状辅助，不能仅凭颜色辨别。

## 9. 纯前端技术与部署契约（P0）

### 9.1 允许

- React + TypeScript + Vite；Three.js / React Three Fiber；GSAP；SVG/Canvas；纯 TypeScript 有限状态机或轻量状态管理。
- 数据、规则、术语、研究文件使用随站点打包的 JSON/Markdown/静态资源。
- localStorage 保存简单设置与学习进度；IndexedDB 保存较大模拟记录；浏览器生成下载文件。
- Node.js 仅用于**本地开发与静态构建**，生产不启动 Node 业务服务。
- 静态托管平台正常提供 HTML/JS/CSS/模型/字体文件。

### 9.2 禁止

- Flask、FastAPI、Express 业务后端、Next.js API Routes、Serverless Functions、远程数据库和认证服务。
- 外部 LLM API、真实网络爬取、真实远程 MCP 接入、必须依赖第三方业务接口的核心功能。
- 在浏览器中硬编码任何秘密 API Key；通过“隐藏的云函数/中转代理”规避上述限制。
- 部署后需要数据库迁移、后台守护进程或后台任务。

### 9.3 部署要求

- 产物为静态 `dist/`；GitHub Pages 项目子路径下静态资源与路由刷新正常；必要字体、模型、图标、数据不依赖 CDN。
- 下载完成并缓存必要静态资源后，核心模拟无任何外部**业务**网络请求（离线完整体验若要求首次离线访问，则额外设计静态缓存/Service Worker，不应偷换为默认承诺）。
- WebGL 不可用时应回退到 2D/SVG 导航与信息；减少动态效果与移动端交互优先级不能忽略。

## 10. 无障碍与性能

- 文字使用 HTML；常规正文对比度目标 ≥4.5:1，大字 ≥3:1；重要状态不只依靠色彩。
- 支持可见焦点、键盘访问、Esc 关闭/取消、可点击替代拖拽、减少动态效果、跳过开场。
- 主要桌面设计基准 1440×900，兼顾 1920×1080 与 16:10；平板折叠 Inspector，移动端使用简化 2D 和底部操作抽屉。
- 桌面渲染目标 60fps，低档目标尽可能维持可操作（参考 30fps）；首屏、帧率与内存预算应在 M0.1 真实测试后复核，**不得在未测量时声称达标**。
- 慎用后期效果、透明层、持续动画；非活动页面停止或降低渲染频率。

## 12. 关键工程约束与推荐模块边界

```text
src/
  app/             # 路由、应用壳、全局状态
  scenes/          # 3D 场景、镜头、时间线（展示层）
  features/
    story/
    atlas/
    laboratory/
    constructor/
    execution/
    reports/
  simulation/
    engine/         # 状态机与确定性流程
    rules/          # 分支及配置校验
    events/         # 结构化执行事件
    evaluation/     # 引用与结果检查
  content/          # 术语、章节、本地参考
  research-packs/   # 虚构教学数据
  shared/           # UI、主题、工具
```

逻辑配置是唯一权威数据源；模拟事件是回放权威数据源；3D 渲染不持有业务真相。构建器逻辑、研究规则、教学内容与可视化要彼此解耦。
