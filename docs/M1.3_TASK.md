## 3. 技术准确性红线

以下概念边界必须在正文和实验中一致：

1.  **Retrieval**
    是根据查询从资料集合中找回相关内容的过程；关键词检索与向量检索是不同方法，不能把简单字符串匹配伪称为语义向量检索。
2.  **Chunking**
    是将文档切分为更适合索引、检索或上下文管理的片段；切分策略会影响上下文完整性与检索结果。
3.  **Embedding**
    是将数据映射为向量表示的技术；本项目可展示预计算的示例向量或二维投影，但不得声称浏览器已调用真实
    Embedding 模型。
4.  **RAG**
    将检索到的外部信息用于生成或回答过程；检索命中不保证答案正确，RAG
    也不等于向量数据库。
5.  **Memory**
    是系统对过去信息的保存与后续复用机制；它与当前上下文窗口、RAG
    检索结果不是同义词。
6.  **Skills** 是可复用的任务方法、指令或工作流程封装；Skill
    本身不自动授予工具权限，也不必然是可执行程序。
7.  **Agent**
    的定义依具体系统而异；本项目以能根据状态/结果选择后续步骤的教学模型进行说明，不把所有聊天机器人都称为
    Agent。
8.  **Agent Loop**
    是观察状态、选择动作、执行并依据结果继续或结束的循环模式；必须明确何时终止，避免无限循环。
9.  **Workflow** 通常表示预先定义或受约束的步骤流；不能绝对化地宣称所有
    Workflow 都完全固定，也不能宣称 Agent 总是优于 Workflow。
10. **Harness** 指围绕模型/Agent
    的运行与控制环境，可涉及工具执行、状态管理、循环控制、权限、日志等；不是另一个模型，也没有唯一通用实现。
11. **Orchestration**
    是任务步骤、工具或多个参与者的协调机制；与单个工具调用不同。
12. **Multi-Agent** 涉及多个 Agent 或角色的协作/分工；增加 Agent
    数量不保证准确率、速度或质量提高。
13. **Permissions**
    定义哪些主体可对哪些资源执行哪些操作；界面中的授权开关必须真正影响模拟执行规则。
14. **Sandbox**
    是限制执行范围与资源访问的隔离机制；前端演示只能模拟隔离策略，不得声称形成真实安全边界。
15. **Prompt Injection**
    是不可信输入试图影响系统指令或行为的风险；不能宣称一个关键词过滤器可彻底防御所有攻击。
16. **Guardrails**
    是输入、输出、工具调用或流程层面的限制与检查组合；不应描述为绝对安全保证。
17. **Tracing**
    记录一次运行中的步骤、输入输出摘要、状态和时间顺序；不得把模拟日志伪称为真实模型遥测。
18. **Evals**
    是使用定义好的任务、标准和判定方法评估系统行为；必须区分单个示例演示与具有统计意义的全面评测。

## 4. Story 主线与章节衔接

三章继续围绕"虚构校园活动整合可行性研究"，但不要求在本阶段完成全站最终叙事。

### Chapter 04 / RETRIEVE, THEN REASON

研究问题：已连接工具拿回资料后，系统怎样找到相关内容、切分文档、组织上下文，并区分可复用方法与可保存信息？

教学推进：Chunking → Retrieval → Embedding 示意 → RAG → Memory / Skills
的职责比较。

章节结尾明确：检索与上下文增强可以改善信息可用性，但不保证来源可靠，也不自动解决执行控制与安全问题；自然引出
Runtime。

### Chapter 05 / FROM STEPS TO CONTROL

研究问题：研究任务为什么需要状态、循环、执行边界和协调策略？

教学推进：Workflow 与 Agent Loop 的差异 → Harness 的运行职责 →
Orchestration → Multi-Agent 的分工与成本。

章节结尾明确：更复杂的执行结构也可能产生错误、循环或不一致；自然引出
Reliability。

### Chapter 06 / TRUST, LIMIT, VERIFY

研究问题：系统如何限制不当操作、处理不可信资料、追踪执行过程并评估结果？

教学推进：Permissions → Sandbox → Prompt Injection → Guardrails →
Tracing → Evals。

章节结尾总结：可靠性来自多层约束、证据与评估，不来自单个"安全开关"；为
M1.4 的知识宇宙整合铺垫。

每章提供学习目标、概念入口、至少一个实验入口、结果解释、上一章/下一章导航及返回
Atlas 的路径。不得强制锁关；章节动画应简洁并允许跳过。

## 5. Lab 01 · KNOWLEDGE LAB

### 目标

让用户观察文档切分、检索、Embedding 示意、RAG、Memory 和 Skills
的差异，理解它们如何影响同一研究任务。

### 必须实现

1.  使用本地打包的虚构校园活动资料。展示文档、片段边界、片段
    ID、元数据和原文定位。
2.  提供至少两种切分预设，例如按段落切分、按固定示意长度切分；显示切分可能造成的语义边界问题。长度只能作为演示参数，不能假称真实
    Token 计数。
3.  提供关键词检索模式；如果实现向量检索概念演示，必须使用明确标注的预计算示例向量/二维投影，或清楚说明其为简化的数学演示，不调用真实
    Embedding 服务。
4.  展示查询、候选片段、匹配分数/匹配理由与最终选中片段。分数必须对应真实实现的本地规则，不得随机生成。
5.  展示 RAG 流程：查询 → 检索 → 选中文档片段 → 组织上下文 →
    规则驱动的模拟答案；没有证据时输出"资料不足/未验证"，不得捏造来源。
6.  提供 Memory
    对比：当前任务上下文、可保存的本地偏好/历史摘要、外部文档检索结果分别呈现；保存与清除行为有明确说明，不能自动把所有资料当作记忆。
7.  提供 Skills 对比：启用/停用一张预设"公告核验方法"Skill
    卡，展示方法步骤变化；启用 Skill 不得自动增加工具权限。
8.  支持重置实验，并展示每项设置如何影响结果。

### 验收底线

-   切分参数改变后，片段边界与检索候选确实更新。
-   检索排序由确定性本地算法决定，同一输入得到同一结果。
-   Memory、RAG、Skills 三者在 UI 和逻辑中是不同机制。
-   不调用远程 Embedding、LLM、搜索或数据库服务。
-   所有来源都能回到实际存在的本地资料条目。

## 6. Lab 02 · RUNTIME LAB

### 目标

用同一研究任务对比 Workflow 与 Agent Loop 的执行控制方式，并解释
Harness、Orchestration 和 Multi-Agent 的职责。

### 必须实现

1.  提供同一组任务步骤与资料，让用户切换 Workflow 与 Agent Loop
    教学模式。
2.  Workflow 模式使用可视化的预定义流程；Agent Loop
    模式根据本地模拟状态与确定性规则选择下一步。
3.  两种模式共享相同资料、工具能力与权限边界。不得为了让某种模式"赢"而暗改数据或成功率。
4.  每一步都生成结构化事件，至少包含
    `eventId`、`runId`、`stepType`、`status`、输入/输出摘要、来源
    ID（如适用）和分支原因。
5.  展示明确的最大步数、终止条件、重试上限与错误处理，确保循环必定可终止。
6.  以叠加层/Inspector 展示 Harness
    的职责，例如状态、工具调用、权限检查、错误处理与日志；不要把 Harness
    画成另一个模型。
7.  展示 Orchestration 的任务分配/步骤协调，并提供一个受控的 Multi-Agent
    角色演示，例如 Researcher、Verifier、Reporter。
8.  Multi-Agent
    每个角色有明确输入、输出、职责和交接事件；不得通过并行播放动画假装真实并发。
9.  结果解释至少包括完成状态、步骤数、工具调用次数、重试次数、未解决问题与来源覆盖；所有指标都来自本地模拟事件。
10. 支持播放、暂停、逐步前进、选择事件查看详情及重置运行。

### 范围边界

本实验是用于学习概念的最小规则模拟，不是 M2 的完整可配置 Agent
Constructor 或高级 A/B
实验室。允许比较两种控制模式，但不实现多套任意配置的长期保存、复杂统计面板或完整实验档案管理。

## 7. Lab 03 · RELIABILITY LAB

### 目标

让用户通过可观察的安全事件理解权限、沙箱、提示注入、Guardrails、Tracing
与 Evals 的关系及边界。

### 必须实现

1.  提供一组本地虚构资料，其中一份包含明显标记的恶意/不可信指令，例如要求忽略研究规则或泄露不应访问的数据。必须标记为"教学用模拟提示注入样本"。
2.  将文档内容视为不可信数据，不允许其内容直接修改应用的系统配置、权限或实验规则。
3.  提供权限配置示例，例如允许读取公开公告、禁止访问私有记录、禁止执行未授权操作；权限切换必须真实影响模拟工具的允许/拒绝结果。
4.  提供 Sandbox
    概念演示，展示可访问资源白名单、被隔离的操作和边界说明；清楚注明这只是前端规则模拟，不构成真实系统隔离。
5.  提供 Guardrails
    检查示例，至少覆盖输入/工具调用/输出中的一种以上检查；展示命中规则、阻止原因与可能的漏检边界。不得宣称可彻底防御提示注入。
6.  生成可筛选的本地 Tracing
    事件链，记录规则检查、工具请求、允许/拒绝、来源使用和终止原因。
7.  提供一组固定 Eval
    样例和明确评分标准，例如：是否遵守权限、是否将不可信文本当作指令、是否有证据支持结论、是否正确报告不确定性。
8.  每项评估必须显示样例输入、预期规则、实际模拟结果、判定理由；分数由确定性规则计算，不得随机生成。
9.  用户切换权限/Guardrails
    配置后，重新运行应产生可解释的事件与评估差异。
10. 显示"通过这些演示不代表真实系统已通过安全认证或全面评测"的明确说明。

### 验收底线

-   被拒绝的操作不能同时显示为成功。
-   不可信文档不得覆盖系统配置或提升权限。
-   每个 Eval 结果都能定位到相应事件与判定规则。
-   关闭动画后，事件与结果仍正确。
-   不能把教学模拟称为真实渗透测试、真实模型安全测试或生产级防护。

-   三个实验共享一致的主工作区、参数区、Inspector、事件/结果区，不应设计成风格不一的独立小游戏。
-   3D
    只承担空间关系与状态提示；可读正文、事件详情、评分理由必须使用可访问的
    HTML/2D 组件。
-   重要状态不能只靠颜色表达；成功、拒绝、警告和模拟状态都需要文字或图标。
-   支持键盘操作、焦点可见、移动端单列/抽屉布局、`prefers-reduced-motion`
    和 WebGL 失败时的 2D 信息访问。
-   实验不需要等待长动画才能继续操作；暂停或减少动态效果不影响逻辑结果。

## 10. 纯前端与安全红线

-   运行时所有业务逻辑在浏览器内执行；生产输出仅为静态资源。
-   禁止 Flask、FastAPI、Express、API Routes、Serverless
    Functions、云端数据库和远程业务 API。
-   禁止真实 LLM API、远程 Embedding API、真实 MCP
    Server、实时搜索或运行时拉取外部知识内容。
-   技术参考资料可以作为普通外链供用户自行打开，但不能成为应用正常运行的依赖；核心资源需随静态构建打包。
-   可使用 localStorage/IndexedDB
    保存用户明确产生的本地学习进度和实验设置；提供合理的重置/清除方式，不能静默覆盖旧数据。
-   所有模拟运行都需清楚标记 `SIMULATION / 本地模拟`，不得宣称是真实 AI
    推理或真实安全评估。
-   未经用户要求不推送 GitHub、不部署上线、不执行破坏性 Git 操作。
