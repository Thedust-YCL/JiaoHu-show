> 阶段：M1 · KNOWLEDGE UNIVERSE / M1.1

## 2. 不可突破的技术与内容红线

1. React + TypeScript + Vite 等现有技术栈为主，尊重仓库当前实现；Node.js 仅是**开发/构建**环境，不是生产后端。
2. 运行期仅使用本地静态资源、本地 JSON/TS 数据、本地状态管理、localStorage/IndexedDB。不得调用远程 LLM、业务 API、云存储或隐式创建 Serverless/API Routes。
3. 部署产物必须是静态资源并支持 GitHub Pages 的项目子路径；避免根路径硬编码、刷新后路由失效。
4. 区分知识、系统配置和执行轨迹三类权威数据：**Knowledge Graph ≠ System Graph ≠ Execution Graph**。知识内容变更不能让 Agent 配置或历史 Run 被改写。
5. 解释准确性高于视觉炫酷：LLM ≠ Agent；MCP ≠ Tool；Skills ≠ 工具权限；RAG ≠ Memory；Workflow ≠ Agent；Harness ≠ 第二个模型。
6. 真实技术资料与 M0.4 的**虚构研究公告**严格分隔。参考资料使用经核验的来源元数据；不能编造官方文档 URL、作者、更新日期与引用。未审校的文字必须明确标记 `draft`。
7. 保存用户已有构建器配置、M0 研究记录、开场偏好、学习进度，任何 schema 调整必须具备兼容读取、迁移、异常恢复；禁止静默清空。
8. 不强推、不改写历史、不做破坏性 Git reset；未经用户要求不主动远程部署或推送。

## 4. 内容 schema 与访问接口

在适配当前项目的前提下，建议建模为如下概念；不要为了逐字复制示意接口而破坏仓库现有设计：

```ts
type ContentStatus = 'outline' | 'draft' | 'reviewed' | 'published';
type RelationType = 'USES' | 'PART_OF' | 'RELATED' | 'CONTRASTS';

type Concept = {
  id: string;                     // 永久稳定，供图谱与学习记录引用
  chapterId: string;
  order: number;
  title: { zh: string; en: string };
  aliases: string[];
  contentStatus: ContentStatus;
  oneLiner?: string;              // 简明定义；未审校则明确草稿状态
  understand?: string[];          // 对新人解释
  inspect?: string[];             // 深入机制、边界、可选结构化示例
  misconceptions?: Array<{ claim: string; correction: string }>;
  example?: { label: string; body: string; isSimulated: boolean };
  experimentId?: string;          // 只有真实存在的实验才填
  sources?: Array<{ id: string; title: string; url?: string; reviewed?: boolean }>;
};

type KnowledgeRelation = {
  id: string;
  sourceId: string;
  targetId: string;
  type: RelationType;
  description: string;
  directed: boolean;
};
```

要求：

- 分离**基础元数据**与**深度正文内容**；未完成概念依然能出现在目录/搜索/Atlas，但不能自动算已学完。
- 统一 `getConcept(id)`、`getChapter(id)`、`getConceptsByChapter(id)`、`searchConcepts(query)`、`getRelations(id)` 等功能；函数名依实际项目可调整，但不要多份手写过滤逻辑散落在组件。
- 支持中英文名称、别名、部分匹配；搜索词大小写兼容，空查询和零结果状态清晰。
- 关系边**有明确解释和方向**，`RELATED` / `CONTRASTS` 默认不是“强依赖”。`PART_OF` 需特别审校，不为了显示某种线型而编造。
- M0.3 既有边应迁移至统一 source，且在 Atlas 表达和知识页关联列表中语义一致。
- 技术来源若无可靠可用 URL，先保留内部待审校状态；不要用假引用让界面显得完整。
- 统一页面/节点的可用性状态（已发布/预告），导航只能指向真正可用的实验，或给出明确的不可用提示。

## 5. 学习进度与数据安全

应延续 M0.3 已有 `unexplored`、`exploring`、`experiment_completed`、`related_discovered` 的语义；**优先采用多标志或时间戳**，避免一个单枚举导致“完成实验后不能标记发现关联”。

最低要求：

- `visitedAt`、`lastViewedAt`、`experimentCompletedAt?`、`relatedDiscoveredIds?` 等语义字段可选；还可记录最后阅读的章节/知识节点。
- 访问知识页记录“探索中”，不代表“通过考试”；只有完成实际存在的实验才记录 `experiment_completed`。
- 学习记录单独储存，不混进 Constructor 配置或 Research Run。
- 存储提供 `schemaVersion`、旧键读取或迁移、数据校验、坏记录容错及非破坏性回退；不能因不认识新章节 ID 就清空已有状态。
- 允许导出学习进度 JSON 作为可选加分项，**不是 M1.1 必做**；禁止发送数据至远端。

## 6. 最小 UI 范围

- Story：提供六章节**目录结构与章节定位**，显示已有和待完善状态；暂不制作六章完整电影级滚动叙事。
- Atlas：复用现有 M0.3 真实可用节点图；扩展概念索引时避免把 26 个尚未审校的节点全部用已完成高亮呈现。可为 `outline` 节点提供可筛选但弱化的入口，或者暂只绘制已开放节点，并在目录列出建设中概念。
- Knowledge Node：开发/改造一个复用模板，含标题、章节、UNDERSTAND/INSPECT、常见误解、来源状态、关联概念、实验入口/未开放说明。
- Tool Calling：保留 M0.3 已完成的教程与实验，不因换模板丢失事件联动、返回导航和学习进度。
- Lab：为当前可用实验建立稳定关联；不可用实验显示“后续阶段开放”，没有可点击的假运行按钮。
- 跨视图：从 Atlas、Story 可进入同一 `conceptId`；从知识页返回之前的上下文（至少可回上一级与 Hub），不重置 M0.4 研究 Run。
- 视觉：遵守 `DESIGN_SYSTEM.md` 的黑曜基底、精密线条、Cyan 活动信号和清晰中文；不为建设数据架构破坏现有 AZ-CORE 01、开场与控件风格。

## 7. 推荐实施顺序

1. **Audit**：检查 M0 代码与存储事实，列出可以复用的 10 节点数据、既有关系、Tool Calling 页面、学习进度模型和导航机制。
2. **Model**：统一 6 章、36 概念的元数据 schema，确定命名和版本规则。
3. **Migration**：迁移/适配 M0.3 10 节点及其已审校正文和边关系，保持持久化 ID 与 UI 行为兼容。
4. **API & Tests**：实现内容查询、搜索、关系验证、章节查询、schema 数据校验；先补纯函数/数据测试。
5. **Learning**：完善学习状态与旧存储的兼容性，避免数据丢失。
6. **UI Integration**：接入可用的六章目录、知识详情统一模板、Atlas/Tool Calling 导航，不做整站大改。
7. **Quality**：执行测试、类型检查、生产构建、关键 M0 全链路回归及 GitHub Pages 路径核查。
