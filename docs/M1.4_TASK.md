## 2. Atlas：完整知识图谱整合

### 2.1 数据要求

1.  Atlas 读取 M1.1
    的统一知识注册表与内容接口，不在页面里复制维护概念正文。
2.  所有 36 个概念均有唯一稳定
    ID、名称、章节归属、内容状态和有效详情路由。
3.  图谱关系来自统一关系数据，不为视觉填充随机连线。
4.  每条关系至少具有起点、终点、类型和说明；有方向性的关系必须明确方向。
5.  `outline` 或 `draft`
    概念可以展示，但必须准确标注状态，不得伪装成完整课程。
6.  图谱节点、详情页、章节目录与实验入口使用同一套 ID 与映射规则。
7.  处理孤立节点、失效目标、重复边、缺失章节等异常；合理的孤立节点可保留，但需有审查记录。

### 2.2 必须实现的交互

-   缩放、平移、恢复全图视图。
-   点击节点显示名称、章节、简短说明、内容状态与可用操作。
-   双击或显式按钮进入详情；避免单击同时触发互相冲突的操作。
-   高亮选中节点与直接相邻节点，其他节点适度降噪。
-   按章节筛选节点。
-   按名称、别名和关键词搜索；搜索结果可以聚焦目标节点。
-   按关系类型筛选（如 `USES`、`PART_OF`、`RELATED`、`CONTRASTS`，以实际
    schema 为准）。
-   查看关联概念及关系说明。
-   从 Atlas 进入知识详情或对应 Lab；Lab
    不可用时显示明确状态和替代路径。
-   恢复全图、清除筛选，避免用户迷失。
-   提供键盘或列表式替代入口，让不便使用拖拽的用户也能探索。

### 2.3 视觉与性能

-   延续 `DESIGN_SYSTEM.md` 的深色科研终端视觉，不重做品牌。
-   节点颜色、形状或图标可表达章节/类型/状态，但不能只靠颜色传达信息。
-   选中、悬停、键盘聚焦和不可用状态有明确反馈。
-   图谱布局稳定；刷新后不应无故大幅随机跳位。若布局算法有随机性，使用固定种子或缓存布局。
-   连线不能遮盖全部标签。缩放时可减少标签密度，但必须保留搜索和详情入口。
-   低性能设备可减少阴影、粒子和过渡；图谱基本功能不得依赖 WebGL。

## 3. Story：六章连续叙事与学习路径

### 3.1 六章叙事主题

沿用现有章节 ID 与正式名称；如以下名称与仓库有差异，以 `PRD.md`
和知识注册表为准，不得无理由重命名持久化 ID。

  -------------------------------------------------------------------------------------------------------------
  顺序              主题              核心问题                                 下一章衔接
  ----------------- ----------------- ---------------------------------------- --------------------------------
  01                Intelligence      模型如何处理输入并生成输出？             生成回答需要什么上下文？

  02                Context           指令、上下文与限制如何影响结果？         模型如何调用工具与外部能力？

  03                Connection        工具调用与 MCP 如何连接能力？            获取资料后如何检索和组织知识？

  04                Knowledge         Retrieval、RAG、Memory、Skills           多步骤任务如何被控制与协调？
                                      如何分工？                               

  05                Runtime           Workflow、Agent Loop、Harness 如何协作？ 如何约束、观察并评估运行？

  06                Reliability       权限、隔离、Guardrails、Tracing、Evals   总结完整系统并进入自由探索
                                      有何作用？                               
  -------------------------------------------------------------------------------------------------------------

叙事须体现真实的因果与技术边界，不得为戏剧性宣称某项技术必然导致某种结果。

### 3.2 每章页面结构

每章通过共享模板呈现：

1.  章节编号、标题与一句核心问题。
2.  学习目标：完成本章后用户应该能解释或区分什么。
3.  本章概念列表及学习状态。
4.  简洁叙事开场与核心示意。
5.  关键概念入口，可进入 `UNDERSTAND` / `INSPECT`。
6.  对应 Lab 入口及其验证目标。
7.  章节总结：关键结论、边界与常见误解。
8.  上一章、下一章、返回 Atlas 和自由探索入口。
9.  本章进度摘要；进度来自真实学习事件，不显示虚构百分比。

### 3.3 Story 播放与导航规则

-   用户可跳过动画或叙事序列；跳过不代表已学习。
-   可从任意章节进入 Atlas 或任一可用概念，不强制锁关。
-   再次进入 Story 时恢复合理位置，同时允许重播。
-   章节切换显示标题、当前状态和返回路径。
-   转场复用现有电影化运镜与 AZ-CORE 01，但转场失败不得阻止内容显示。
-   支持 `prefers-reduced-motion`，提供低动态或直接切换模式。
-   不强制每次访问都播放长开场。
-   Story 文案与知识详情共用定义，避免两套内容冲突。
-   章节结束可建议下一步，但不能阻止自由探索。

### 3.4 学习路径

至少提供两种路径：

-   **Guided Path**：01 → 06 推荐学习路径，显示章节目标与建议实验。
-   **Free Exploration**：通过 Atlas、搜索、关联概念与实验入口自由跳转。

两种路径共享同一进度数据；切换路径不得重置进度或重复创建状态。

## 4. Knowledge Journal：本地学习记录

### 4.1 目标与数据来源

Journal
是个人本地学习记录，不是社交产品、云端账号或行为监控工具。只能由真实应用事件生成，例如：

-   用户实际打开并查看概念详情。
-   用户切换到 `INSPECT` 深入内容。
-   用户启动 Lab 并完成定义好的关键操作。
-   用户查看实验结果或完成实验总结。
-   用户完成章节总结或明确标记章节完成。
-   用户从概念跳转到关联概念或实验。

页面加载、自动播放动画、自动滚动或程序预取内容不得被记为学习完成。

### 4.2 最低功能

1.  显示六章概览、概念探索数、已完成实验数和最近活动。
2.  显示最近记录：日期/时间、事件类型、章节/概念/Lab ID 与回访链接。
3.  支持按章节和活动类型筛选。
4.  从记录跳回相关知识详情或 Lab。
5.  区分"已探索"和"已完成"；打开一次不等于掌握。
6.  可清除 Journal 活动记录，清除前说明影响范围。
7.  清除活动记录不得误删 Agent 配置、研究运行记录或其他命名空间。
8.  新用户有清晰的空状态、推荐起点和可跳过提示。
9.  未实现的统计不得用虚构数据填充。
10. 明确数据只保存在当前浏览器/设备范围内，并说明清除方式。

### 4.3 学习状态定义

以现有 schema 为准；若语义不清，采用以下最低区分：

-   `not_started`：没有有效学习事件。
-   `explored`：用户实际打开并查看内容。
-   `in_progress`：完成部分学习操作，但未达到完成条件。
-   `completed`：完成内容明确规定的关键操作或总结。
-   `reviewed`：用户主动再次查看已学内容，仅在现有系统需要时使用。

不得自动推断 `mastered`
或声称用户已经掌握知识。若现有项目使用其他状态，保留兼容映射并文档化。

### 4.4 进度与记录隔离

-   阅读进度、Lab 完成状态、Journal 活动记录、Agent
    配置和研究运行记录使用清晰分离的命名空间。
-   不得以 schema 升级覆盖或清空旧数据。
-   若需迁移，必须实现可测试的非破坏性迁移、默认值和损坏数据容错。
-   限制记录数量或提供合理裁剪，避免无限增长。
-   不记录敏感输入或不必要的完整用户文本。
-   Journal
    清除、全部学习进度清除、构建器配置重置必须是不同操作，并分别解释后果。
-   清除前二次确认；清除后 UI 与存储一致。
-   不提供无实际行为的导出/同步按钮；若提供导出，必须在浏览器端真实生成并测试。

## 5. 跨系统整合与状态一致性

### 5.1 统一数据来源

-   Atlas、Story、Chapter Hub、Knowledge Detail、六个 Lab 与 Journal
    使用同一套章节、概念和关系 ID。
-   概念正文只在统一知识数据层维护，不在 Story、Tooltip 和 Journal
    中复制整段定义。
-   Lab 完成状态由各 Lab 明确发出完成事件，并由统一进度服务写入。
-   同一概念从任何入口打开，都定位到同一详情页与同一学习状态。
-   别名用于搜索，但跳转与存储映射到稳定 ID。
-   章节重排不得破坏已有深链或本地学习记录。

### 5.2 六个 Lab 的联动

M1.2/M1.3 的六个实验必须在章节、Atlas 与 Journal
中具有一致名称、入口、状态和返回路径：

1.  Token Lab
2.  Context Lab
3.  Tool Calling / MCP Lab
4.  Knowledge Lab
5.  Runtime Lab
6.  Reliability Lab

每个 Lab
至少提供目标说明、明确入口、当前概念/章节关联、可操作内容、真实完成判定、返回路径和错误提示。M1.4
不重写实验底层规则，只在必要时增加统一入口、完成事件和导航联动。

### 5.3 全局导航

确保用户始终可以访问：

-   Story / Chapters
-   Atlas
-   Labs
-   Knowledge Journal
-   当前概念/章节上下文
-   返回 Control Hub 或主入口

窄屏可改为抽屉、分段导航或单列布局，但不可隐藏核心内容且不给替代入口。
