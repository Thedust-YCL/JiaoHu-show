## 实际发现

本轮未发现 P0/P1。以下为应修复的 P2，既包括本轮新增接缝，也包括 M3.1 明确要求审计却尚未闭环的既有表现问题。行号为发现时工作树行号。

### R01 — 新运行仍展示上一 Run 的核心事件

- 位置：`src/features/execution/components/runtimeWorkspace.js:131`、`:154`。
- 触发：运行若干步或打开一条已有事件的历史，再点击“新运行”（或相同快照重跑），不执行第一步。
- 原因：共享 core 仅在 `renderDetail` 的 `if(e)` 中调用 `core.render(run,e)`。零 step Run 不进入该分支；新的 `publishPresentation` 已清除 3D 聚焦，但 caption/SVG 还保留上个 Run 的事件。
- 影响：当前“就绪/0 步”的新运行旁边展示旧事件及失败/成功链路；在 WebGL fallback 下尤其容易被理解成当前已执行内容，违反真实状态和 Review Focus 3。
- 最小修复：在统一 render 中始终以当前 Run 和当前选中事件（允许 null）调用 `core.render`，同时清理无事件的 scene focus。增加“有事件→新运行→core 不含旧事件”的真实 DOM 回归。

### R02 — 抽屉里的确认框被全局 Tab 圈定抢走

- 位置：`src/app.js:1022`、`:1887`。
- 触发：360–430px 或平板打开 Inspector，从中打开 Starter/加载/重置等自定义确认框；从初始“取消”按 Tab 到“确认”，再按 Tab。
- 原因：确认框局部 Tab handler 没有停止传播；window handler 在判断确认框之前运行 `currentDrawer()` 的 Tab 圈定，preventDefault 后试图聚焦已经被确认框 inert 的原抽屉。
- 影响：正向 Tab 在“确认”停住，无法正常循环到“取消”；Shift+Tab 产生不对称行为。背景隔离改进在嵌套浮层时破坏键盘预期。
- 最小修复：确认弹层打开时优先由它独占全局键盘处理，或局部 Tab handler 阻止传播。验证 Tab/Shift+Tab 两方向循环及 Escape 返回触发按钮。

### R03 — 带事件上下文的 report 路由恢复成 execution

- 位置：`src/app.js:1877`、`:1878`；`src/features/execution/components/executionWorkspace.js:473`。
- 触发：旧执行台有 Run，选中一条事件，切换“研究报告”，再刷新或从其他页面浏览器 Back 到该 report history entry。
- 原因：`openExecution({view:'report',eventSequence})` 先切 report，再 seek；seek 内部为了事件定位会切回 execution。恢复路由时 `applyingRoute` 阻止同步 hash，最终地址 `#/report` 与实际内容 execution 不一致。
- 影响：刷新/Back 无法恢复用户刚在阅读的报告，违反 Review Focus 2 和导航内容一致性。
- 最小修复：先 seek 再设置最终 view，或为恢复型 seek 增加保留 view 的选项；覆盖带有非空 eventSequence 的 report 刷新与前进/后退。

### R04 — 旧 Execution 的上一次 Run 知识往返串到最新 Run

- 位置：`src/features/execution/components/inspector.js:133`；`src/features/execution/components/executionWorkspace.js:499`、`:502`；`src/app.js:1748`。
- 触发：已有两次不同 Run，在旧执行台选“上一次运行”，选择工具事件，打开 Tool Calling 知识节点，再用页面返回或浏览器返回。
- 原因：路由上下文只携带 eventSequence，未携带 runId；工作区重建时 activate 始终 attach `history[0]`，再把上一次 Run 的序号应用到最新 Run。
- 影响：相同序号可能对应另一个工具或成功/失败状态，用户追溯原事件时看到了别次运行。保留序号并不足以保留事件上下文。
- 最小修复：路由/UI session 同时保存 runId 与 eventSequence，恢复时从已有研究历史选中原 Run，再 seek；若原 Run 已不可用，应明确提示，不能静默换 Run。无需改历史存储格式或引擎。

### R05 — A/B 未保存保护遗漏离站及档案打开

- 位置：`src/app.js:1067`；`src/features/comparison/components/comparisonWorkspace.js:190`、`:193`。
- 触发一：Constructor 已保存且干净，运行 A/B 后不保存实验，刷新或关闭页面。
- 触发二：保留一个未保存的 A/B 对比，进入档案并打开或重跑另一实验。
- 原因：beforeunload 只检查 Constructor；当前实验仅在内存 session。新增保护只覆盖“新建实验”，档案打开/重跑直接替换 `session.experiment`。
- 影响：用户尚未保存的两侧快照、轨迹、报告会无提示消失，违反 A14。明确点击 RUN/按原条件重跑本身是否需要确认未作为缺陷；这里针对离站和切换所查看对象的静默替换。
- 最小修复：共享当前 A/B 未保存判定/状态，覆盖 beforeunload 与档案替换；成功保存后解除保护，保存失败仍保留。正常站内导航继续保存 session，不需反复提示。

### R06 — reduced-motion 仍压缩播放完整五机位运镜

- 位置：`src/scenes/intro/timeline.js:87`；`src/app.js:393`。
- 触发：prefers-reduced-motion 开启，首次访问或重播开场。
- 原因：reduced 虽把时长设为 0.75 模拟秒、assembly/lit 立即完成，但 sample 仍无条件 `camera.lerpVectors(active.from,active.to,e)`；结束后 `enterIdle` 也可能继续 tween。
- 影响：缩短时长同时加快了五段空间运镜，不符合“静态姿态 + 极短淡入/禁止强制空间运镜”的既定规则。
- 最小修复：reduced 时保留 HUB 固定相机，结束进入 idle 采用 instant；用几个时间采样验证 reduced 相机固定，真实浏览器检查仍可跳过/进入主界面。
- 注意：主验收的固定 800ms 等待失败，不能单独当本问题证据。app 将每帧 dt clamp 到 0.05，SwiftShader 慢帧可能让 0.75 模拟秒超过 800ms 墙钟；验收应以有界等待实际 phase 为准。
