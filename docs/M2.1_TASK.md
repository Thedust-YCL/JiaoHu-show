## 2. 核心体验流程

`BUILD → CONFIGURE → VALIDATE → SAVE → PREVIEW`

1.  用户进入 Constructor，看到当前 Agent 配置与 AZ-CORE 01。
2.  从模块目录点击安装模块；可选拖拽仍可使用，但点击安装必须完整可用。
3.  安装、移除或禁用模块后，3D 核心、2D System View、Inspector
    与预检同步更新。
4.  用户选择模块，在 Inspector 修改配置。
5.  系统实时校验必填项、范围、依赖、冲突和权限规则。
6.  用户查看 Preflight，了解配置摘要、问题和本地模拟边界。
7.  用户保存、复制或加载本地配置。
8.  配置以稳定、可序列化的数据形式交给 M2.2；本阶段不实现高级运行引擎。

配置草稿、已保存配置和当前选中模块必须区分。未安装模块不能显示为已启用；无效模块必须解释原因。动画只是状态表达，不能代替
2D 信息。

## 3. Agent Configuration Schema

先检查仓库是否已有等价
schema；有则扩展兼容，避免重复建模。字段名可服从项目约定，但至少覆盖以下语义：

``` ts
type AgentConfiguration = {
  schemaVersion: number;
  configId: string;
  name: string;
  description?: string;
  createdAt: string;
  updatedAt: string;
  modules: AgentModuleInstance[];
  connections: ModuleConnection[];
  settings: {
    executionMode: "workflow" | "agent-loop";
    maxSteps: number;
    maxRetries: number;
    requireApprovalForRestrictedActions: boolean;
  };
};
```

每个模块实例至少包含 `instanceId`、`moduleType`、`enabled`、`order` 和
`config`。连接包含稳定
ID、起点实例、终点实例、连接类型和有效状态。可由配置推导的依赖边不必重复持久化，但必须文档化。

要求：

-   `schemaVersion` 用于未来迁移；ID 唯一且稳定。
-   复制配置时生成新 `configId` 和安全的新实例 ID，并修复内部引用。
-   时间戳格式一致；配置可序列化，不包含函数、DOM、WebGL
    对象或运行时句柄。
-   每类模块有默认配置、字段 schema 和验证函数。
-   未知模块/字段不能导致崩溃或被静默删除；显示兼容警告并提供恢复路径。
-   数值、字符串、数组和存储大小有合理限制。
-   UI 表单和配置验证共享同一规则。
-   保存、加载后语义一致。
-   配置对象不包含学习进度、Journal、Research
    Run、动画状态或任何秘密/API Key。

## 4. 模块目录：10 类模块

每个模块在统一注册表中声明稳定类型
ID、名称、描述、分类、默认配置、可编辑字段、依赖、冲突、可用状态、相关知识概念
ID 和本地模拟说明。

### 4.1 Model

本地模拟的模型行为预设，例如
`balanced`、`careful`、`concise`，以及回答风格、教学用上下文预算、确定性选项。必须明确不连接真实模型，不允许输入
API Key。

### 4.2 Instructions

研究目标、系统指令、输出格式与约束。具备长度限制、空值校验、重置默认值。不得把不可信研究资料自动合并为系统指令。

### 4.3 Context

任务背景、上下文模式、是否包含任务简介/检索证据、教学用预算和本地资料
ID。明确区分 Instructions、当前 Context、RAG 证据和 Memory；预算不是实际
Token 计数。

### 4.4 Tools

至少复用本地模拟工具：`announcement_search`、`document_reader`，以及项目已有的证据比较工具（若存在）。每个工具展示输入/输出、权限、失败情况和本地模拟标记。禁止远程
URL 请求。

### 4.5 MCP

展示本地预设连接档案和静态能力目录，模拟协议/能力发现。明确区分
MCP、Server、Tool 与 Model；不连接真实 MCP Server、不发网络请求。

### 4.6 Retrieval

配置本地检索模式、Top-K、切分策略和来源元数据。复用 M1.3 Knowledge Lab
的逻辑，不建立第二套检索算法。向量示意必须标明是预计算或简化演示，不得声称调用真实
Embedding。

### 4.7 Skills

选择本地预置 Skill，至少提供"公告核验方法"。保存稳定 Skill
ID，不复制知识正文。Skill 提供方法/指令/流程，不自动授予工具权限。

### 4.8 Memory

配置 `disabled`、`session` 等本地模拟模式及允许复用的本地条目。明确区分
Context、RAG 和 Memory；不得自动保存所有输入，不得把 Journal 当作 Agent
Memory。

### 4.9 Runtime

配置 `workflow` /
`agent-loop`、最大步数、最大重试、证据不足时是否停止、受限操作是否需要审批。这些参数供后续运行引擎消费；M2.1
只负责配置与预检。

### 4.10 Guardrails

配置公开公告读取、私有记录访问（默认拒绝）、结论是否必须有证据、不可信指令覆盖阻止、受限操作审批。显示最小权限原则与安全边界；本阶段不实现完整运行时安全分支。

## 5. 依赖、冲突与验证逻辑

必须实现可测试、确定性的纯逻辑验证层，不得将规则零散地写在 UI 组件中。

至少校验：

-   不可重复模块的重复安装。
-   模块/Skill/Memory/资料 ID 不存在。
-   Retrieval 没有可用的本地资料源。
-   MCP 能力未在静态目录注册或 MCP 模拟模块未启用。
-   工具已启用但权限策略拒绝该操作。
-   需要审批的操作没有启用审批。
-   无效的 `maxSteps`、`maxRetries`、上下文预算或字段类型。
-   禁用模块仍被显示为 active 或仍被连接引用。
-   未保存修改、未知模块和旧 schema。
-   只有视觉意义、没有真实配置含义的连线。

验证结果分为 `error`、`warning`、`info`。每条结果有稳定
ID、级别、标题、说明、相关模块/字段和建议动作；点击问题能聚焦对应位置。同一配置产生相同问题列表，排序稳定。

## 6. 3D、2D 与 Inspector 单一状态源

### 3D 核心

复用 M0.2 的点击装配和可选拖拽。安装、移除、禁用、警告与预检状态映射到
AZ-CORE
01；不得为每种配置硬编码一个独立场景。非法拖拽不能造成半完成的配置修改。

### 2D System View

显示真实模块、依赖关系、启用状态、缺失依赖和冲突。点击节点选中模块并打开
Inspector。自动推导边与用户显式连接必须区分。提供列表式替代视图。

### Inspector

按模块类型显示表单；必填、范围、默认值、错误与警告明确。修改后更新统一配置并触发校验。支持单模块恢复默认。切换配置或离开页面时不得静默丢失未保存修改。

### 状态纪律

3D、2D、Inspector、模块目录和 Preflight
都从同一份配置派生。悬浮、弹窗和选中项属于临时 UI
状态，不写入持久化配置。

## 7. 配置管理与本地持久化

必须实现：

-   保存、加载、复制、重命名、删除配置。
-   恢复默认示例配置。
-   识别未保存修改。
-   删除、覆盖、重置时二次确认。
-   对损坏数据提供错误提示和恢复选项，不静默清空。

至少提供两套可通过同一 schema 校验的本地示例：

1.  `Research Assistant — Starter`：基础校园公告研究配置。
2.  `Research Assistant — Evidence First`：更强调证据来源和核验的配置。

两套配置只是教学示例，不代表真实性能排名或"必然更好"。

存储要求：

-   仅使用浏览器本地存储或项目已有的本地数据库。
-   配置使用独立存储命名空间，不与 Journal、学习进度、研究运行记录混用。
-   保存/加载时重新校验 schema。
-   复制后 ID 唯一，引用完整。
-   删除一个配置不影响其他配置或历史研究记录。
-   schema 升级必须非破坏性迁移并有测试。
-   不保存 API Key、Cookie、密码或其他秘密。

## 8. Configuration Preflight

本阶段实现配置预检，不实现高级执行引擎。预检显示：

-   配置名称、版本、模块数量。
-   已启用模块与关键参数摘要。
-   执行模式、最大步数、重试上限。
-   本地模拟工具、资料源、Skill/Memory 引用。
-   权限策略和需审批操作。
-   error / warning / info 列表。
-   是否满足进入后续模拟运行的最低条件。
-   明确的 `SIMULATION / 本地模拟，不连接真实 AI` 声明。

结果必须由真实配置与验证规则计算，不得硬编码"全部正常"。存在 error
时不能显示为可运行；只有 warning 时可以继续，但需明确告知。

如果现有项目有 Run 按钮，可让其进入 Preflight
或显示"高级模拟将在下一阶段启用"，不能制造假的执行成功。

## 10. 视觉与无障碍

-   严格遵循 `DESIGN_SYSTEM.md`，保留 AZ-CORE 01、电影式开场与 M0.2
    装配视觉。
-   优先沿用现有布局；可采用模块目录、中央 3D/2D
    视图、Inspector/Preflight 的三栏或可折叠工作区。
-   3D 不得挤压表单可读性；窄屏可切换标签页、抽屉或上下布局。
-   安装、移除、禁用、保存、加载、复制、删除和校验失败均有真实反馈。
-   键盘可完成主要操作；焦点可见，弹窗正确管理焦点。
-   支持 `prefers-reduced-motion`；减少动画不影响逻辑。
-   错误、警告、禁用和通过状态不能只用颜色表达。
-   WebGL 不可用时，模块目录、Inspector、2D System View
    和配置管理仍可用。
-   不加入无真实数据来源的评分、准确率预测或排行榜。

## 11. 纯前端与安全红线

-   所有配置、验证、保存与预检在浏览器执行，生产产物仅静态资源。
-   禁止业务后端、云端数据库、账号服务、Serverless API 和远程配置服务。
-   禁止真实 LLM、MCP Server、Embedding、实时搜索和外部工具调用。
-   所有工具/MCP 能力来自随静态构建打包的本地目录。
-   用户文本不能作为脚本执行；避免 `eval`、动态代码执行和不必要的 HTML
    注入。
-   若实现配置导入，必须执行 schema
    校验、字段白名单和大小限制；未知字段显示警告。
-   模块状态必须明确标记为本地配置/模拟，不伪装成真实连接。
-   不主动推送、部署或执行破坏性 Git 操作。
