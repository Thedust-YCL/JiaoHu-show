## 1. P0 技术与事实边界（任何阶段均不能突破）

**纯前端约束**：生产环境必须是 HTML/CSS/JavaScript/模型/字体/JSON 等静态资源组成的浏览器应用；不允许 Flask、FastAPI、Express 业务后端、API Routes、Serverless Functions、云数据库、账号系统、后台守护进程、远程 RAG 服务或后端模拟器。

**零真实 AI API**：不得调用真实 LLM、真实联网检索、真实 MCP Server、真实网站爬虫或把 API Key 藏在前端。Node.js 仅可用于本地开发、测试和构建；静态 `dist/` 可发布到 GitHub Pages 项目子路径。

**知识真实性**：页面应持续标识 `SIMULATED / 本地教学模拟`。虚构大学、活动公告、公告日期、研究场景结论均为教学样本。不能伪称系统正在真实思考、真实上网、访问学校数据或连接真正的 AI Agent。

**研究输出边界**：M0.4 报告由**本地结构化资料、明确规则和可解释模板**生成；不是由真实语言模型自由撰写。“证据充分”“更正成立”只能表达为“**在本教学数据和模拟验证规则中成立**”。

**部署与离线**：所有关键业务资料与规则随站点打包；用户加载静态文件后不需要业务网络即可继续模拟。不要把“无业务请求”误写成“首次打开网站也可以完全离线”；PWA/Service Worker 不是本阶段必需。

## 3. M0.4 用户体验 Golden Path（交付后必须一镜到底跑通）

1. 用户打开网站，M0.1 电影开场可播放/跳过，进入 AZ-CORE Control Hub。
2. 在 M0.2 Constructor 中通过点击或拖拽装配 `Announcement Search` 与 `Document Reader`，设置只读权限及 `searchScope/maxResults/readMode/includeMetadata`，3D、2D、Inspector 同步。
3. 可进入 M0.3 Atlas / Tool Calling 学习页，再返回原来的工具定位与配置，不丢失状态。
4. 进入 `MISSION 001 / 校园活动信息整合可行性研究`，观察虚构教学说明，选择研究策略：`VERIFY_REVISIONS` 或 `COLLECT_ONLY`，故障模式沿用 M0.3 既有设置。
5. 点击 `RUN SIMULATION`，从当前已确认 Constructor 配置生成**不可变** Run 快照；模拟事件在 Execution Graph / 3D 核心 / Inspector / Timeline 同步表现。
6. 在有足够可见资料的前提下，系统发现 `10 月 18 日` 与 `10 月 20 日` 公告差异；若策略允许并且有明确更正链证据，则将旧信息标记为“被更正”，而非删除历史；否则保留未解决冲突。
7. 点击核验事件，查看**规则依据、来源关系、所使用的可见字段**；手动暂停并返回先前事件比较。
8. 打开研究报告，读到每条主要发现的引用标记及局限；点击引用进入对应文档片段，并定位该片段在本次研究中的读取/核验事件。
9. 返回报告时保留原阅读位置、段落选中与筛选状态；可下载 Markdown。
10. 禁用 Reader、将 `readMode` 改为摘要或关闭核验，再发起 `NEW RUN`：**报告、证据状态与轨迹必须按照配置变化**；旧 Run 仍可检查，且不被新配置覆盖。

**成功的视觉体验**：执行有“前因后果”，不是先播放炫酷动画再显示预制报告。**成功的教学体验**：用户能说清楚为何 10/20 可以或不可以采信、为何某些结论只能写“未证实”。

## 4. MISSION 001：数据包与事实建模

### 4.1 数据规模（M0.4 精简集）

| 数据类别 | M0.4 建议范围 | 必需内容 |
|---|---:|---|
| 虚构校园公告 | 6–8 份 | 包括 10/18→10/20 更正对、至少一组未可消解冲突、正常一致的公告 |
| 技术方案比较卡 | 3 份 | 规则自动化 / 固定 LLM 工作流 / Agent 式流程的概念性优劣及适用条件 |
| 可被引用的正文片段 | 每公告 ≥1 个 | 明确 sourceId/chunkId/原文片段及可核事实 |
| 有效更正关系 | ≥1 组 | 相同事项、明确官方更正、发布关系可核查 |
| 未决矛盾 | ≥1 组 | 相互不一致但没有可靠更正关系，不能瞎猜 |
| 检索/读取故障条件 | 沿用 M0.3 + 必需能力缺失 | 由 Run 选项或真实配置决定，不随机造假 |

该规模是 M0.4 **垂直样本**；PRD 中“8–12 份公告、4–6 份技术资料、多个故障/注入情境”是未来扩展参考，**不是本阶段硬性全部完成**。数据较少时更应确保每项证据真实进入流程。

### 4.2 文档示例（所有具体主体为虚构）

- `notice-001`：虚构大学学生事务中心发布创客分享会**原公告**，发布日期 `2026-10-12`，活动日期 `2026-10-18`。
- `notice-002`：同一有权发布方在 `2026-10-13` 发布**明确更正公告**，正文说明该活动日期改为 `2026-10-20`，且 `supersedes: ["notice-001"]`。两者应有同一事项的稳定 `eventKey`。
- `notice-003` 与 `notice-004`：不同渠道对另一场虚构活动提供互相冲突的日期，但**没有被证实的 supersedes 关系**，仍须保留“未核实”而非武断选较晚日期。
- 其余文档提供可检索的背景与研究资料，覆盖 `campus_events` 和 `all_notices` 范围差异，避免 Search 配置成为无效装饰。

### 4.3 推荐数据结构（示例，字段名可适配现有仓库）

```ts
interface ResearchSource {
  sourceId: string;            // 稳定 ID；保留 M0.3 已存在 ID
  title: string;
  publisherId: string;         // 来源机构身份，不只显示中文名称
  publishedAt: string;         // ISO 日期
  eventKey?: string;           // 同一事项的稳定身份
  eventDate?: string;          // 文档中宣称的活动日
  supersedes?: string[];       // 明确更正的原公告 ID
  validity?: 'active' | 'superseded' | 'unknown';
  chunks: Array<{
    chunkId: string;
    text: string;
    claimIds?: string[];
  }>;
  tags: string[];
  isFictional: true;
}

interface EvidenceClaim {
  claimId: string;
  subject: string;             // e.g. eventKey
  predicate: string;           // e.g. event_date
  value: string;               // e.g. 2026-10-20
  sourceId: string;
  chunkId: string;
  visibility: 'exposed' | 'not_exposed';
}
```

- 示例只是逻辑约定；读取现有 M0.3 样本时，**保留已有 sourceId、chunkId**。不要在同一场景里为了开发便利重新随机命名文档。
- 真实教学可见的“研究事实”，必须能从当前模拟工具**返回给任务的内容**推导，不可从隐藏的完整数据包偷偷读出结论。
- 内部引擎维护的 `sourceId/chunkId` 用于追踪和调试；它们不能自动等同于公开可见的发布日期、发布主体、`supersedes` 等证据字段。
- 测试中应检查循环更正、未知 supersedes 指向、重复文档 ID、无效日期、相同 ID 对应不同正文等错误；无效资料不会直接造成崩溃或被采信。
- 如果使用报告引用技术比较卡，要标注其为教学提供的架构说明，而不是“某虚构学校真实证明这种方案更先进”。

### 4.4 阅读范围与可见证据（P0：不能用“上帝视角”作弊）

| M0.2 配置 | 研究端真正可使用的信息 | 对核验的影响 |
|---|---|---|
| Search 不可用 | 无新检索到的公告 | 不能输出来源已找到的事实 |
| Search `maxResults=3` | 最多三个符合条件的搜索项 | 不得直接使用本次未检索到的第 4 份公告 |
| Reader 不可用 | 仅使用真实返回的搜索摘要和 ID | 不得假装读过公告正文或更正说明 |
| Reader `readMode=summary` | 只接触已配置的摘要文本 | 如摘要不含完整更正证据，状态必须是待核实 |
| Reader `readMode=full_text` | 可接触本地文档完整内容 | 可用于证据比对，但不能自动保证来源可信 |
| Reader `includeMetadata=false` | 对研究判定层不暴露来源机构/发布时间等已关闭元数据 | 涉及发布关系的自动核验须降级为无法充分核实 |
| Reader `includeMetadata=true` | 按实际数据暴露来源机构、发布时间及显式更正关系 | 满足其他规则时允许完成核验 |

- 可以保留内部索引与调试元信息，但**报告中用于支持事实的证据必须来自对本次执行可见的响应**；Inspector 可以明确区分“模拟工具返回的公开字段”与“用于跟踪的内部 ID”。
- 为 M0.4 的 Golden Path 应提供一个说明明确的“**研究更正事件**”预设，使用户配置能够实际检索到 `notice-001` 与 `notice-002`。不要为了固定展示矛盾而绕过 `maxResults`、`searchScope` 或 Reader 权限。
- `readMode=summary` 若摘要恰巧写有更正日期，也只可以据摘要给出**有限的线索**；不能凭未读取的正文和未暴露元数据声称已核验完整更正关系。

## 5. 证据链、冲突与更正核验规则

### 5.1 提取与分组：从可见文档出发

1. 从 Search 可见结果决定可读取的 `sourceId` 集合。
2. Reader 按现有 M0.2 配置逐项返回摘要/全文及可选元数据；每次调用在 M0.3 事件规范中留下 `tool.call`、`tool.result` 或 `tool.error`。
3. 以预设、可检查的 claim 提取映射从**实际暴露的文本片段**获得事实（如活动日期）；本阶段不调用 LLM 自动抽取。
4. 对 `eventKey + predicate` 相同但 `value` 不同的可见声明，生成冲突候选。若缺少 eventKey 关联证据，应标注“可能是相关事项”而非强行认定相同活动。
5. 检查是否具有足够的可靠来源、更正元数据、全文片段与先后关系；不具备时保持 `unresolved`。
6. 将结构化判断、ruleId、参与的 claim/source/chunk、未满足的规则与最后状态写入当前 Run 证据结果及事件。

### 5.2 更正成立的必要条件（本教学规则）

`REVISION_CONFIRMED` 必须**同时满足**：

- 两份相互影响的公告都在本次 Run 的实际可见证据集中；没有由内部库暗中补齐。
- 同一个 `eventKey` 或等价可信事项身份，冲突的是同一个事实字段（如 `event_date`）。
- 较新公告正文**明确说明更正**，并指向或可证实它更正的是哪份旧公告；`supersedes` 元数据单独存在但正文未被读取时不足以宣称已阅读核实。
- 必需的发布来源/发布时间等元数据已由模拟工具返回；发布主体为同一授权机构或数据包中明确具备该事项更正权的机构。
- 新公告发布时间晚于被更正公告；双方关系无循环、未指向不存在的资料，且文档没有被模拟数据中明确撤回或标记为无效。
- 本次运行策略为 `VERIFY_REVISIONS`。若选择 `COLLECT_ONLY`，只收集并呈现冲突，不自动宣布更正已确认。

不满足任一条件：进入 `UNRESOLVED` 或 `INSUFFICIENT_EVIDENCE`，并附上**具体缺失原因**。**禁止**仅以“事件日期更晚”或“公告发布时间更晚”作为充分核验依据。

### 5.3 分支与事件设计

| 情况 | 必需事件语义 | 报告可表述的程度 |
|---|---|---|
| 证据足够，策略 VERIFY | `evidence.conflict_detected` → `evidence.revision_confirmed` | “在模拟公告链中，10/18 已被更正为 10/20” |
| 相同证据，策略 COLLECT_ONLY | `evidence.conflict_detected` → `evidence.verification_skipped` | “资料报告 10/18 与 10/20，尚未进行更正关系核验” |
| 双方有冲突但无 supersedes 链 | `evidence.conflict_detected` → `evidence.conflict_unresolved` | “存在分歧，不能根据日期擅自裁决” |
| 缺 Reader / 仅读摘要 | `evidence.insufficient_detail` | “仅收集到搜索结果/摘要，不能证实正文中的更正” |
| 缺元数据 | `evidence.metadata_missing` → 未决 | “无法核对发布关系/主体，暂不确认更正” |
| 搜索缺失 / 模拟超时 | 沿用 `validation.blocked` / `tool.error` | “研究缺少所需来源，不产出事实性定论” |

事件应遵守 M0.3 的字段要求（稳定 `eventId`、`sequence`、`phase`、`status`、`actorId`、`toolId`、`sourceIds`、`chunkIds`、`branchId`、`ruleId`、`message`），并可选增加 `claimIds` / `evidenceIds`。不要新建另一套无法回放的“报告事件流水”。

### 5.4 错误和异常

- 同一文档被检索两次：去重结果及证据声明，不重复计算引用支持数。
- 更正链循环或多条互相矛盾更正：标记为数据缺陷/待核实，不能用“最新胜出”悄悄消解。
- 读取错误：可以输出有限报告，但不能给未读取正文的事实强引用。
- `maxResults` 只返回旧公告：报告须保留仅有旧信息的有限认识，不能凭隐藏的新公告决定“已经更正”。
- 限制符号及日期字段：报告展示与计算必须来自同一结构化来源，不能出现轨迹说 10/20、报告写 10/18 的不一致。
- 不可信资料内嵌类似“忽略规则”的文本时，须按普通**显示文本**处理，不作为模拟引擎命令执行；完整 Prompt Injection 实验不在本轮范围。

## 6. 运行选项与现有 Constructor 的边界

### 6.1 不增加一个假的“验证插件”

M0.2 构建器目前只有两个真正可装配、可配置、可禁用的模拟工具（Search、Reader）。M0.4 不得为展示核验功能而暗地加入第三个可调用 AI 模块。新增的是 Execution 启动前明确可见的**本地规则策略**：

```ts
// 合并到已有 SimulationInput / RunOptions 中；保持旧 faultMode 字段兼容
interface ResearchRunOptions {
  evidencePolicy: 'VERIFY_REVISIONS' | 'COLLECT_ONLY';
  faultMode: 'normal' | 'search_timeout';
}
```

- 此策略控制本次 Run 的证据检查规则，不是 Search/Reader 的替代品，也不是 MCP 或技能。
- 默认值建议 `VERIFY_REVISIONS`，但用户可以明确切到 `COLLECT_ONLY` 并查看实际分支变化。
- 运行前显示：当前实际装配模块、权限/读取模式、任务包版本、研究策略与故障模式。
- 不允许有一个与已确认 Constructor 配置冲突的“Search Enabled”“Reader Enabled”影子开关。
- 若旧配置无 `evidencePolicy`，迁移时可以明确使用文档约定的默认值，不能因读不到字段就崩溃。

### 6.2 本次 Run 和旧 Run 必须隔离

- 点击 `RUN SIMULATION` 时冻结并校验 Constructor 快照、RunOptions、任务数据版本，所有后续工具可用性与证据由这个快照决定。
- Replay 与 Report 均消费**同一 Run 的 artifacts**；不从当前可变配置里重新生成旧报告。
- 新配置只有 `NEW RUN` 后生效；原 Run 的事件、来源、报告、分支依据保持不变。
- 可以在 M0.4 中保留最近 2 次 Run 方便演示前后差异，也可以保留最近一次并通过导出保存历史；**最低必须保证切换/重跑时旧 Run 的信息不会在仍被查看时被悄悄覆盖**。采用历史列表时控制本地容量并给出清理策略。
- 如果本地存储为空间不足，显示可恢复提示；不能清空 Constructor 配置或造成资料引用失效。

## 7. 研究报告：从证据模型生成，而不是拼接“看起来像 AI”的作文

### 7.1 报告内容（最低六大部分）

| 部分 | 最低要求 | 信息来源 |
|---|---|---|
| R1 · 研究任务与范围 | 解释“校园活动分散发布是否适合用 Agent 整合”及教学局限 | 任务模板 + Run 选项 |
| R2 · 核心发现 | 对实际检索/阅读到的公告做可追溯摘要，必要时出现 10/18→10/20 | 证据 claims + 核验状态 |
| R3 · 方案比较 | 对“规则自动化 / 固定 LLM 工作流 / Agent 式流程”做有条件的概念比较 | 内置技术说明卡 + 可观察任务约束 |
| R4 · 证据引用 | 每条重要事实附 [S1]、[S2] 等链接，能够打开来源原文片段 | sourceId + chunkId + eventId |
| R5 · 局限与风险 | 标明模拟资料、缺少工具、资料不足、核验未完成及本方案运行边界 | Run outcome + unresolved items |
| R6 · 研究建议与待验证 | 在不同任务条件下给出条件性方案建议，而不是“Agent 一定更好” | 固定决策规则 + 证据局限 |

- 报告必须使用**可检查的结构化模板/块**渲染；所有模板文字和数据映射本地实现，未调用真实模型。
- 方案比较是依据**教学设计的典型技术权衡**作条件性分析，不是实际跑过三种系统后的性能对比。UI 明确区分“概念比较”和“本次模拟验证”。
- 有效更正链的表达范例：**“在本次虚构公告资料中，更正公告将活动日期由 10 月 18 日调整为 10 月 20 日 [S1][S2]。”** 不得概括为“学校官方已经确认最新日期”，造成真实世界联想。
- 若没找到新公告，只能说“本次资料中发现 10 月 18 日的公告”，**不能**声称“这就是最新有效日期”。
- 未证实结论应显式标记“未核实/证据不足”，不能被模板自动转成确定事实；不存在证据时不显示假引用。
- 报告可在 Search 缺失或工具超时的分支输出**有限/失败说明**，但不得强行填满假数据。“没有足够证据形成完整报告”是合法结果。

### 7.2 建议结构化结果（不要求逐字照搬）

```ts
interface ReportClaim {
  id: string;
  text: string;
  status: 'supported' | 'unresolved' | 'insufficient';
  citationIds: string[];
  relatedEventIds: string[];
  basisRuleId?: string;
}

interface ReportCitation {
  id: string;               // 如 S1；展示标号可由稳定排序派生
  sourceId: string;
  chunkId: string;
  eventId: string;          // 支撑该片段进入本次研究的读取/检查事件
  excerpt: string;          // 实际可见片段快照
}

interface ResearchReport {
  schemaVersion: number;
  runId: string;
  missionId: string;
  missionVersion: number;
  status: 'complete' | 'partial' | 'blocked';
  sections: Array<{ id: string; title: string; claimIds: string[] }>;
  claims: ReportClaim[];
  citations: ReportCitation[];
  limitations: string[];
  recommendations: string[];
}
```

- `ReportCitation` 可以通过已有 refs + 快照解析，但必须在版本变化、页面刷新和修改配置后仍指向**当时实际使用的文本**。
- `ReportClaim` 的 `status` 由规则与证据计算；不能让 UI 选择“绿色”就自动生成 supported 状态。
- 引用 ID 的排序与去重稳定；同一个 source/chunk 可以被多条 claim 使用，引用编号应统一，不能每次点击都生成新编号。
- 不允许 `dangerouslySetInnerHTML` 直接展示数据包文本；HTML 语义化呈现、必要时使用安全的文本节点。

### 7.3 可量化但不造假的信息

报告 Inspector 可展示以下**真实来自当前模拟计算**的指标：

- 已检查的资料数量 / 已读取全文的资料数量；两者必须区分。
- 有事实引用支持的研究发现数量 / 实际需要证据的发现数量。
- 本次可见的冲突数量、已处理数量、未解决数量。
- 工具调用次数、错误次数、回放事件数量。

若分母为零，显示“无可评估事实”或“尚无证据”，不能输出误导性 100%。以上不是现实世界准确率、事实正确率或模型智能评分。

## 8. 来源浏览器与报告引用的双向导航

### 8.1 用户操作

1. 点击报告中的 `[S2]`（或其他引用标识）。
2. 打开 `SOURCE INSPECTOR`，显示标题、虚构发布主体、文档的可见元数据、引用片段、相关 claim 和“虚构教学资料”标签。
3. 对原始文本高亮当前引用的**真实片段**；摘要模式仅显示本次确实拿到的摘要内容，不允许展示“本次已阅读全文”幻觉。
4. 点击 `VIEW IN EXECUTION`，跳转到本次 Run 实际读取或核验该片段的 `eventId`，并同步 3D 活动链路/2D Execution Graph/Timeline/Inspector。
5. 通过 `BACK TO REPORT` 返回原段落与滚动位置；必要时可从 Execution 再次跳回报告对应 claim。

### 8.2 溯源数据纪律

- 不能只链接到资料标题；至少定位到 **sourceId + chunkId + 本次使用的 eventId**。
- 如果报告断言更正关系，必须同时引用旧/新公告相关片段或使用明确对应的多条引用；单引一个不包含更正关系的摘要不够。
- 无阅读权限或未阅读的全文不能作为正文级引用。仅凭 Search 摘要的声明应标为“仅搜索摘要线索”。
- 引用已损坏/指向不存在的资料时显示“历史记录引用不可解析”，并阻断“已验证”展示；不能静默定位到另一份同名文档。
- 选择来源只是 UI 导航，不会修改原来的配置、证据判断与历史 Run。

## 9. 执行空间与视觉设计联动

### 9.1 四个视图，各司其职

| 视图 | 权威数据 | M0.4 新增表现 |
|---|---|---|
| Atlas / Knowledge | 术语与语义关系数据 | 为 Source Verification / Evidence Checking 提供上下文**说明**，不强制新增 10 节点之外的知识图谱 |
| Constructor / System Graph | M0.2 确认配置 | Run 前展示本次策略；修改配置仅影响下次 Run |
| Execution Graph / Replay | M0.3 当前 Run 的事件序列 | 增加 conflict/revision/insufficient/report 事件与对应可选分支 |
| Report / Source Inspector | 本次 Run 的结构化证据与报告 | 可定位来源、证据结论、局限、回放事件及导出 |

Knowledge Graph、System Graph、Execution Graph 仍是**三张不同的图**；报告/Source Inspector 不是第四张随意连线的知识图。

### 9.2 动画与系统状态映射

- `evidence.conflict_detected`：Execution Graph 两条证据路径在检查节点汇合，Amber 冲突标记出现；不能把两份资料自动混成一份。
- `evidence.revision_confirmed`：显示旧事实被更正的**历史可追溯状态**，新结论进入报告草稿区；用 Verified Green 表示“规则内核验成立”，旁边必须有文字。
- `evidence.conflict_unresolved`：维持双方资料、未决状态与限制，避免为了动画好看而删除矛盾节点。
- `evidence.metadata_missing` / `evidence.insufficient_detail`：只高亮已获得数据，缺失的来源路径显示为虚线/占位而非“读取成功”。
- `report.generated`：不是虚构模型打字过程；是由模板装配产生报告块的演示效果。
- `PAUSED`：冻结运行数据脉冲与正在播放的结论呈现，不影响阅读现有证据、事件或 3D 静态观察。

所有事件动画仍由同一 `eventId` 控制；暂停/Seek/倍速/减少动态效果不能改变报告和事件内容。

### 9.3 页面排版原则

- 与 AZ-DESIGN v1 一致：Void `#07090D`、Panel `#10151D`、Signal `#77D8EC`、Attention `#F0BD78`、Verified `#80D9B4`、Error `#FF8585`，语义色不得反向滥用。
- Report 采用**科研档案阅读模式**：左侧可折叠报告目录，中间清晰正文与引用标记，右侧来源 Inspector；底部可打开与报告项关联的 Execution Timeline。
- 大标题英文可保持品牌气质，中文正文必须高可读；避免把大段报告正文贴到 WebGL 画布或用滚动劫持代替正常阅读。
- 细线、刻度、微光是辅助，真正的视觉高潮是“冲突被发现 → 证据链展开 → 决策结果回写报告”，不是满屏能量粒子。

## 10. 客户端导出与运行记录

### 10.1 Markdown 导出（P0）

- 以**当前选中的 Run** 的 `ResearchReport` 为唯一导出源，生成 UTF-8 `.md` 文件；浏览器通过 Blob / URL.createObjectURL / download 实现，无后端。
- 文档头部明确写入“AGENT / ZERO · SIMULATED RESEARCH REPORT / 虚构教学研究报告”，包含任务、数据集版本、配置摘要、研究策略、生成方式与局限说明。
- 核心发现保留 `[S1]` 等引用标识；末尾附参考来源表（虚构来源、sourceId、chunkId、已读取的片段/摘要）和未解决问题。
- 防止 Markdown 注入/语义混淆：对外部字段进行适当转义或受控模板处理，不允许数据中提供任意可执行链接作为可靠事实；文件名可用 `AGENT-ZERO_MISSION-001_<run-id>.md` 形式。
- 下载失败或浏览器阻止下载时有明确提示；导出不修改报告或学习进度。可选提供纯本地 JSON 导出，**但不是必做**。

### 10.2 运行历史与版本迁移

- 延续 M0.3 的 SimulationRun/Replay，报告作为新版本 `artifacts` 或关联的 `report` 挂载，禁止创建只适用于画面的独立影子结果。
- 对 M0.3 无报告的历史运行：允许显示**“旧版运行：只有执行轨迹，尚无结构化报告”**；不得从新资料包悄悄替旧 Run 补造“当时已经验证”的报告。
- 运行记录包含版本信息：`schemaVersion`、`missionId`、`missionVersion`、配置快照、RunOptions、events、evidence、report 或可重建报告所需的完整可见快照。
- 已缓存的旧数据包/旧 Run 引用不可解析时，显示清楚的兼容性提示；不能用当前资料替换旧资料后仍把引用说成可复现。
- 新增的本地存储命名空间由实际仓库选定；不要改写 M0.2 Constructor 的权威键，也不要删除学习进度与 Boot 设置。
- 数据量较大可采用 IndexedDB；若采用 localStorage，应检查容量与序列化失败回退。导出后只撤销 Blob URL，不持久保留额外敏感对象。

## 11. 工程结构与集成策略（尊重真实仓库）

```text
src/
  research-packs/
    mission-001/               # 版本化教学公告与比较卡；保留 mini 稳定 ID
  simulation/
    engine/                    # 扩展 M0.3 运行主流程，禁止第二引擎
    rules/
      evidence/                # 资料可见性、冲突、更正关系、异常
    evaluation/               # 证据与引用一致性检查
    events/                   # 扩展原有事件类型和分支说明
  features/
    execution/                # 在现有 Replay 中扩展冲突/核验/报告事件
    reports/
      components/             # Report Reader, Source Inspector, Citation Link
      state/                  # 当前 Report 选择与导航上下文
      export/                 # 纯前端 Markdown 序列化
  tests/
    research-pack/            # 稳定 ID / 链接合法性 / 数据校验
    evidence/                 # 冲突、可见性、更正、证据不足
    report/                   # 内容、引用、导出与历史版本
    integration/              # Golden Path / 回归 / 静态路由
```

关键边界：

1. **Research Pack 是输入事实集合**，不允许 UI 直接扫描全部 JSON 来补齐本次未发现的来源。
2. **Evidence Evaluator 是纯逻辑**，从本次 Tool Results 的可见证据计算状态与引用。
3. **Execution Events 是唯一可回放的运行记录**，报告引用通过 eventId 锚定进入研究的证据片段。
4. **Report Generator 只消费结构化结果**，不得调用 3D 场景状态或从组件文本反向解析判断。
5. **Constructor Store 仍是配置唯一权威来源**，修改当前配置不更新旧 Run。
6. UI 对未开放的未来功能只显示静态说明或明确标记 Coming Later，不制作无响应假按钮。
