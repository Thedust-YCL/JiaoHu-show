## 2. 启动审计与测量基线

### 2.1 必须先确认

- 框架、构建工具、包管理器、Three.js/GSAP 或其他动效依赖的实际版本与使用范围。
- 路由与静态部署 `base` 路径、代码拆分策略、本地/生产资源路径。
- Canvas/WebGL 初始化与卸载路径，是否存在多个动画循环、重复渲染器或隐式事件监听。
- 六章 Story / Atlas / 六个 Lab / Constructor / Runtime / Comparison / Journal 的实际可访问性。
- 现有测试命令、测试范围、运行条件、失败项以及缺失的关键测试。
- 用户数据结构及版本：Knowledge Progress、Journal、Agent Configuration、Run History、A/B Experiment Archive 等。

### 2.2 测量条件与基线表

至少记录：

- 构建模式：**生产构建预览**优先；开发模式数据不得直接用于对外性能结论。
- 设备：CPU / 内存 / GPU 或可取得的硬件信息；系统版本；浏览器与版本。
- 视口：桌面 1440×900（可补 1366×768）；窄屏 390×844（可补 360×800）；按项目实际适配范围补平板。
- 加载条件：冷启动和热启动分开测；网络节流条件如适用必须注明，不得把本机静态服务假装成真实公网。
- 操作场景：开场 → Hub、Atlas 36 节点交互、六个 Lab、装配/拖拽、连续模拟运行、事件回放、A/B 对比、长时间停留和路由切换。
- 指标：页面可交互时间/浏览器性能迹线、最大资源与主要 chunk 大小、网络请求数量、帧耗时分布、掉帧、JS 堆变化、WebGL 资源对象趋势，以及操作响应异常。

**目标值不是未经测量的保证。** 60fps 是理想目标；负载较高设备以自适应 30fps 与交互可用为合理降级策略。渲染目标可以按桌面约 16.7ms/帧、降级模式约 33.3ms/帧作为参考，但必须结合测量环境和真实交互判断。不要伪称在所有设备上稳定 60fps。

报告中提供 **优化前值 → 优化后值 → 测量条件 → 变化原因 → 代价/风险**。没有基线则不得报告“提升百分比”。

## 3. WebGL / Three.js / 动画优化

### 3.1 渲染循环与可见性

- 检查是否重复创建 `requestAnimationFrame`/GSAP 时间轴，组件卸载是否正确停止。
- 页面切换、标签页隐藏、3D 区域不在视口时，按现有产品要求暂停或减小更新频率；恢复时状态正确。
- 配置变化只更新受影响的节点、材质或状态，不无条件重建整个场景。
- 运行模拟事件由真实 Runtime 驱动，动画只是表现；暂停动画、减速播放或减少动态效果不得改变事件结果。
- 适配 `prefers-reduced-motion`；运动减少但可见状态与操作保持完整。

### 3.2 图形资源与负载

- 审查几何体共享、材质/纹理复用、重复 draw call、灯光/阴影成本、后处理和粒子数量。
- 使用适合项目架构的自适应像素比/渲染质量策略，避免高 DPI 下 GPU 负载失控。
- 视情况优化大纹理、透明对象排序、过度绘制和多层 Canvas；不要为追求分数粗暴删除关键视觉效果。
- 对场景退出、模块移除、资源替换、WebGL 上下文丢失进行生命周期管理；释放本组件拥有的 GPU 资源，避免错误释放仍在共享使用的资源。
- 对 WebGL context lost/restored 进行安全处理；恢复失败时提供 2D 信息与操作路径，不能把错误传播成整个应用崩溃。
- 逐项记录具体优化与复测，避免无证据的大规模“性能重构”。

### 3.3 长时间使用测试

执行重复场景：多次进入/退出核心视图、装配/移除模块、执行模拟、回放、打开/关闭 Inspector、A/B 切换。记录事件监听、渲染循环、堆内存和 WebGL 资源趋势。短期 GC 波动不能直接认定为内存泄漏；关注重复操作后持续增长和无法释放的对象。

## 4. 首屏、分包、字体与静态资源

- 分析构建产物中 JS、CSS、图片、字体、贴图、模型、音视频资源的体积与加载关键路径。
- 检查首屏是否不必要地加载六个 Lab、整个 Atlas、A/B 对比或其他非首屏模块；在确保导航正确的前提下做合理按路由/功能分包。
- 对短小但高频的数据保留简洁的同步获取路径，不盲目异步化导致界面闪烁。
- 优化字体加载和备用字体，避免长时间不可见或明显布局偏移；核心字体/静态资源必须可随项目部署，不依赖外部 CDN。
- 适当压缩、分辨率分级和懒加载图像/贴图；不得破坏关键视觉一致性。
- 检查无用依赖、重复依赖、构建 warning、资源引用和 source map 策略；修改需说明影响。
- 进行 GitHub Pages **子路径的本地构建验证**，确保绝对路径、动态资源路径和 hash 路由/历史路由方案在静态托管下可用；M3.2 不进行正式部署。
- 无需联网调用后端的核心体验必须完全依赖随静态构建打包的本地数据。

**限制：** 不设未经基线支持的全站包体积硬指标，也不把绝对 Lighthouse 分数作为唯一门禁；先分析瓶颈再优化，并明确无法测量的项目。

## 5. 应用响应性与 UI 性能

- 审计频繁更新的播放进度、事件时间线、图谱交互和 Inspector 表单，避免每一帧触发不相关的全应用重渲染。
- 对大型日志/轨迹视图进行必要的虚拟化、分页或限制可见数据量；保证搜索、定位和复制功能不受影响。
- 选择性使用 memoization、批量更新和纯派生数据；不要为了局部提升引入难以维护的全局缓存。
- 输入编辑保持响应迅速；保存、重置、切换配置都遵循 M2.1 的单一数据源。
- Atlas 布局和节点搜索结果应稳定，刷新或筛选后不应随机跳位。
- 所有监听器、观察器、订阅和定时器都需有明确生命周期清理。
- 保证键盘操作、焦点恢复、弹窗和菜单在频繁路由切换后仍正确。

## 6. 业务正确性：完整链路与数据保护

### 6.1 学习链路

验证：Story 六章导航 → Atlas 概念搜索/聚焦 → 分层知识详情 UNDERSTAND / INSPECT → 六个 Lab → Knowledge Journal 记录 → 刷新恢复。确认所有内容仍指向 M1 注册的稳定 ID，不因性能拆包改变路由和进度语义。

### 6.2 Agent 构建链路

验证：装配/移除/启用模块 → Inspector 编辑 → 2D/3D 同步 → Preflight 验证 → 保存/复制/加载/重置 → 错误配置和未知旧模块的处理。不得以动画状态代替真实配置状态。

### 6.3 Runtime 链路

验证：相同的配置快照、任务/本地资料版本、场景与 seed，产生相同业务步骤、分支、证据与结果。事件 ID/时间如包含会变化的展示字段，应与业务确定性比较分开。逐项测试：

- Workflow 与 Agent Loop 的实际规则差异。
- 正常、资料缺失、工具失败一次/持续失败、证据冲突、权限待审/拒绝、最大步数耗尽、提示注入模拟。
- 单步与连续运行的业务结果一致，暂停/继续/取消与重新运行状态有效。
- 角色交接、工具权限、Skills 与 Memory 不发生越权。
- 被拒绝的工具操作不得同时显示成功；资料不足不得伪造肯定结论。
- 研究报告引用指向真实存在的本地来源与事件，而非随机生成的引用号。

### 6.4 A/B 比较公平性

验证同一任务、数据集版本与 seed 下运行两套配置；保存不可变快照。对比指标来自各自运行事件，不得使用手填的“效率提升百分比”“模型准确率”或伪造成本数据。切换 A/B、打开某条运行事件或返回实验档案时，不得混淆配置与结果。

### 6.5 本地持久化与迁移

针对以下数据分别验证：学习进度、Journal、Agent 配置、Runtime 历史、A/B 实验档案。

- 刷新恢复、保存/加载、复制、重命名和删除行为正确。
- schemaVersion 迁移、旧数据兼容、损坏 JSON、存储容量不足、无存储权限等情形得到可理解处理。
- 清除 Journal 不得误删 Agent 配置；删除配置不应破坏已保存的不可变运行快照。
- 不得静默清空旧数据或在迁移中无条件覆盖原始数据。
- 迁移测试必须使用**测试夹具/隔离存储**，不得在用户真实数据上执行破坏性测试。
- 记录保存策略与数据规模上限；不存在“永不丢失”的误导承诺（浏览器数据可能被用户或浏览器清除）。

## 7. 兼容性、无障碍与降级质量门禁

### 7.1 浏览器及视口

建议验证至少：Chromium 系（Chrome/Edge，桌面）、Firefox；Safari/iOS Safari 在可用环境下检查。**没有环境就标记 NOT RUN，不可编造兼容测试结果。**

检查桌面 1440×900、1366×768，平板约 768–1024px，窄屏 360–430px；以产品实际目标为准。至少完整走通“学习一章”和“创建配置→运行→查看结果”两条路径。

### 7.2 无障碍与输入方式

- 键盘操作可到达 Atlas 搜索/列表、Lab、装配替代操作、运行审批与对比；焦点可见。
- 表单错误与对应控件关联，重要状态不是仅靠颜色表达。
- `prefers-reduced-motion` 时停止/减少非必要运动，不改变执行逻辑和可用性。
- 移动端触控目标可操作、弹窗/Drawer 不被遮挡，水平溢出只在合理的表格或代码容器中出现。
- WebGL 不可用/初始化失败时，保留 Story、Atlas 列表、知识详情、2D 配置、Runtime 与 A/B 结果的文字/二维操作。
- 使用自动化检查工具时，不能声称其结果等同完整无障碍人工审计。

## 8. 纯前端、依赖与安全边界审计

- 检查生产构建是否包含 API 路由、Serverless、后端服务或依赖云端业务服务的代码。
- 审核源代码与构建产物中是否存在真实模型 API Key、密钥样例误入发布资源、私有数据或不必要的敏感信息。
- 核查核心运行路径无真实 LLM/Embedding/MCP/实时搜索 API 请求；允许加载同源静态资源和用户主动点击打开普通参考链接。
- 禁止对不可信资料执行代码、HTML 注入或 `eval`；教学用 Prompt Injection 样本只当作本地数据处理。
- 检查用户导入的配置、运行档案、Markdown 导出与 URL 参数是否有合理校验和大小限制；渲染外部/用户文本时采用安全文本方式。
- 检查直接/传递依赖的许可证与已知安全问题；不能把所有告警一律升级成项目阻断，也不能掩盖实际高危且可触达的依赖风险。
- 禁止新增未经用户批准的遥测、云端分析、追踪 SDK 或第三方业务请求。
- 纯前端不意味着所有防护都等同于真实服务端安全控制；应用必须继续标注本地模拟的安全边界。

## 9. 全项目测试策略

### 9.1 测试分层

1. **纯逻辑单元测试**：知识关系、配置 schema、Preflight、检索、Runtime 状态机、重试、权限、种子复现、A/B 指标。
2. **组件/交互测试**：按钮、表单、Atlas 搜索、Inspector、运行控制、审批、Journal、错误/空状态。
3. **端到端主流程**：首次进入→章节学习；概念→Lab→进度；Constructor→配置→Preflight→Run→报告；A/B→档案→导出。
4. **兼容与视觉检查**：多视口、WebGL 失败、减少动效、键盘、重要布局、设计系统回归。
5. **生产构建检查**：本地静态预览、路径与资源正确性、运行时网络边界、关键控制台错误。

优先复用现有 Vitest/Jest/Playwright 等工具（若存在）。新增测试工具必须说明理由；无法执行浏览器端到端测试时记录为 `BLOCKED` 或 `NOT RUN`，并提供明确的 M3.3 风险项。

### 9.2 回归范围

至少覆盖 M0.1–M0.4、M1.1–M1.4、M2.1–M2.3、M3.1 关键行为。不得仅检查“页面能打开”；对装配、报告来源、权限和 A/B 计算等关键逻辑必须进行断言。

### 9.3 测试执行纪律

- 区分 `PASS`（真实验证通过）、`FAIL`（真实验证失败）、`BLOCKED`（客观环境/依赖阻断）、`NOT RUN`（未执行）。
- 每一类结果提供命令/用例/浏览器/测试数据/证据，能复现则附重现步骤。
- 未实际运行 Lighthouse、性能录制、真实移动设备或 Safari 检查时，不能写“已测试”。
- 自动测试通过 ≠ 人工视觉与可用性已通过；两者单独汇报。
- 禁止为让测试变绿而删除断言、跳过关键用例或偷偷改变功能要求。

## 10. 缺陷分级与发布门禁

| 级别 | 定义 | M3.2 处理策略 |
|---|---|---|
| P0 — Blocker | 核心流程不可用、严重数据丢失、真实后端/API 违约、关键权限绕过、无法生产构建 | **必须修复并复测**，否则不得宣称可进入发布 |
| P1 — High | 高概率崩溃、主要实验结果错误、报告引用不可信、关键设备/模式不可操作、严重资源泄漏 | **必须修复或明确禁止发布**，不得以“建议优化”搪塞 |
| P2 — Medium/Low | 局部体验、细微排版、低频非阻断问题、设备差异等 | 记录影响、重现步骤和后续处理优先级，允许作为已知问题进入 M3.3 评估 |

**M3.2 的完成 != V1.0 已发布。** 完成意味着发布技术门禁具备充分证据；M3.3 仍需在实际静态托管环境验证部署、回滚、文档、版本和最终发布手续。

## 11. 推荐实施顺序

1. **Inventory/Audit** — 读取需求、审计代码、检查历史测试和风险。
2. **Baseline** — 运行生产预览性能基线，记录条件和原始数据。
3. **Correctness First** — 修复 P0/P1 正确性、存储迁移、权限、引用和 Runtime/A/B 问题。
4. **WebGL Profiling** — 优化渲染循环、材质/粒子、GPU 资源和可见性，复测。
5. **Bundle & Load** — 检查拆包、静态资源、字体与加载顺序，复测。
6. **UI/Memory** — 处理不必要重渲染、事件订阅和长时间使用问题。
7. **Compatibility/A11y** — 视口、键盘、低动态、WebGL fallback；没测的如实记录。
8. **Dependency/Architecture** — 依赖、许可证、静态部署路径和远程业务请求审计。
9. **Regression/E2E** — M0–M3.1 的全链路回归、类型检查、测试、生产构建。
10. **Quality Gate** — 输出前后数据、A01–A40、缺陷清单和 M3.3 交接。

## 13. 交付的报告内容

### `docs/M3_PERFORMANCE_REPORT.md`

至少包含：

- 测试硬件、浏览器、视口、构建模式和采样方法。
- 主要场景的优化前后数据；未能测量处明确标注。
- WebGL/GPU、JS 线程、内存、首屏加载和资源体积热点。
- 每项优化对应的文件、改动、收益与代价。
- WebGL 降级和减少动画测试结果。
- 后续仍值得优化但不阻断发布的事项。

### `docs/M3_QUALITY_GATE.md`

至少包含：

- M0–M3.1 关键流程与端到端测试结果。
- A01–A40 逐项状态与证据。
- 不同设备/浏览器/视口的实测覆盖和未测范围。
- 完整缺陷清单（P0/P1/P2、重现步骤、归属、修复状态）。
- 配置/研究/学习/实验档案数据保护情况。
- 依赖、纯前端架构、敏感信息与静态部署子路径审计。
- M3.3 的最终发布前工作和风险项。
- **唯一、明确的结论**：`READY_FOR_M3_3` 或 `BLOCKED`，给出理由；该结论不能代替 M3.3 的生产发布验收。

## 14. 最终汇报格式

1. 审计与性能基线（包含测量条件）。

## 15. M3.2 完成定义

只有以下情况全部满足，才可声明 **M3.2 的技术质量验收完成**：

- 真实的性能基线、优化前后结果和测试条件已记录；无法测量部分如实说明。
- 主要 WebGL、加载和 UI 性能热点已处理或有可信的风险处置说明。
- 六章、36 概念、六个 Lab、Constructor、Runtime、A/B 比较、证据报告与 Journal 的关键链路通过真实回归。
- Runtime/权限/引用/本地存储等核心正确性有自动化或可靠的人工证据。
- 兼容性、键盘、低动态、WebGL 降级的实测范围和未测范围均明确。
- 没有仍开放的 P0/P1 发布阻断项；若存在则结论必须为 `BLOCKED`。
- 自动测试、类型检查、生产构建和静态前端边界审计有可复核结果。
- 完整产出性能报告、质量门禁与 M3.3 交接单。

通过后进入 **M3.3：V1.0 正式发布**，完成生产静态部署、真实域名/子路径验证、部署回滚预案、项目说明、版本标记和最终发布验收。
