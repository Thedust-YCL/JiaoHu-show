> **阶段：M0.2 / Assembly Prototype**  
> **基线：PRD v0.7 + AZ-DESIGN v1.0；承接已完成的 M0.1**  
> **任务状态：可直接交给 Codex 开发**  
> **依赖：** `PRD.md`、`DESIGN_SYSTEM.md`、`M0.1_TASK.md`，以及仓库中实际存在的 M0.1 代码。

## 1. 不可突破的 P0 架构红线

- **100% 纯前端**：所有运行时业务逻辑、装配校验、模块配置和本地持久化在用户浏览器执行。
- **不允许业务后端**：禁止 Flask、FastAPI、Express 服务端、API Routes、Serverless Functions、云端数据库、账号系统或任何自建业务 API。
- **不允许真实 AI 调用**：不得请求在线 LLM、联网研究、远程 MCP Server、真实工具服务或 API Key；本阶段只是**工具能力的装配和配置**，不执行真实工具。
- **只依赖静态资源**：React + TypeScript + Vite + Three.js/R3F/GSAP 等现有工具可以保留。字体、模型、代码、素材和必要数据随站点本地打包，生产运行不依赖第三方 CDN。
- **继续支持 GitHub Pages**：`npm run build`（或仓库对应脚本）输出静态资源；处理好仓库子路径、刷新和资源 URL。Node 仅用于开发/构建，不是线上服务。
- **必须诚实标识**：界面常驻适当的 `SIMULATED / 本地教学模拟`；不把能力装配、动画脉冲或状态面板宣称为真实 API / MCP 调用或真实 Agent 推理。
- **不修改冻结品牌**：`AGENT / ZERO`、`A/0`、暗色精密科研风、机械轨道+黑曜几何核心、Cyan/Amber/Green/Red 状态语义以及 3D+2D 双视图原则继续有效。

## 3. 两种示范模块与端口模型

第一版必须有**两种类型不同、可独立操作、可同时装配**的模块，不能只是两个外观不同但共享一个布尔开关的按钮。

| moduleId | 显示名称 | 类型 | 对应 3D 端口 | 配置要求 | 状态影响 |
|---|---|---|---|---|---|
| `announcement_search` | Announcement Search / 公告检索 | 模拟搜索工具 | `SEARCH_PORT` | 选择搜索范围与结果数量；只读权限 | 具备合法配置与授权时 Ready |
| `document_reader` | Document Reader / 文档读取 | 模拟读取工具 | `READER_PORT` | 选择读取方式；只读权限 | 具备合法配置与授权时 Ready |

### 3.1 工具配置的具体字段（本地模拟参数）

**Announcement Search**
- `searchScope`：`all_notices` / `campus_events`；可显示为“全部公告 / 校园活动”。
- `maxResults`：`3` / `5` / `10`。
- `readPermission`：允许 / 拒绝，仅作为本地模拟权限配置。

**Document Reader**
- `readMode`：`summary` / `full_text`（摘要 / 全文，仅代表后续模拟策略）。
- `includeMetadata`：布尔值，是否请求包含发布日期、来源等元数据。
- `readPermission`：允许 / 拒绝。

这些参数**在 M0.2 不触发真实数据搜索或文档读取**。必须形成可保存、可校验、可被后续 M0.3 引擎读取的结构化配置。可以给字段设置合理默认值，但未经授权不得把模块直接视为 Ready。

### 3.2 端口兼容性

- `SEARCH_PORT` 仅接受 `announcement_search`；`READER_PORT` 仅接受 `document_reader`。
- 本阶段每种模块最多装配 **1 个实例**；重复添加应定位现有实例并提供“查看配置/移除”，不产生叠加的 3D 模型。
- 模块应有稳定 `moduleId`、端口应有稳定 `portId`，不能用模型 mesh 的位置或临时 DOM 下标判断身份。
- 可以在 L3 轨道接口已有视觉形态上增加对应热点与占位；如需移动位置，仅做避免遮挡和改善命中的小幅调整。
- **禁用不是移除**：禁用后 3D 模块继续在位、连接线不再显示活动状态，2D 中显示“Disabled”；重新启用不需要重新装配。
- **移除才释放接口**：移除后 3D 模块撤离、2D 节点消失、正式配置移除；重新添加视为新一次装配。

## 4. 状态机与单一权威数据源

### 4.1 数据职责划分

1. **Persisted Configuration（权威）**：已经确认的模块实例、端口、参数、权限、启用状态和配置版本。建议由一个独立 store 管理。
2. **Assembly UI Session（瞬态）**：悬停、选中、预览、当前拖动、目标端口、动画进度、提示浮层；不作为业务真相。
3. **Derived Validation（派生）**：根据模块参数、权限、端口兼容性和启用状态推导 Ready/Unconfigured/Invalid，不从 3D 发光状态推导。
4. **View State（展示）**：Assembly / System View、Inspector 当前显示、摄像机视角；不单独存模块配置。

**唯一数据流**：用户输入 → 校验/状态更新 → store → 3D、2D、Inspector 的表现更新。动画成功与否不能反向决定业务数据是否存在。

### 4.2 状态定义（与 PRD 一致）

| 逻辑状态 | 定义 | 本轮动作 |
|---|---|---|
| `Available` | 模块尚未装配 | 选择、预览 |
| `Preview` | 用户正在预览位置，尚未提交 | 确认、取消、选择接口 |
| `Attached` | 已提交装配且占用接口 | 查看或进入配置；可能尚未满足 Ready 条件 |
| `Unconfigured` | 已装配但缺少必要参数/授权 | 配置、移除、禁用 |
| `Ready` | 已装配、已启用、参数有效且授权满足 | 修改、禁用、移除 |
| `Disabled` | 已装配但用户关闭该模块 | 重新启用、修改、移除 |
| `Invalid` | 已装配的配置不满足兼容性/格式规则等 | 查看明确错误、修复或移除 |

实现时允许把 `Preview` 建成独立的瞬态模式，把 `Attached` 作为持久结构关系，把 `Unconfigured` / `Ready` / `Disabled` / `Invalid` 作为派生有效状态；**不强制将这七个名字写成同一个枚举字段**，但对用户行为和界面解释必须一致。

`Hover` / `Selected` / `Focused` / `Dragging` 是额外 UI 状态，可与 Ready、Disabled 等共存。不要把一次模拟工具调用的失败混入模块永久的 Invalid 状态。

### 4.3 转换规则

- `Available → Preview`：点击模块或开始合法拖拽；只展示投影，不持久化。
- `Preview → Available`：取消、Esc、无效释放到画布空处；不得留下残余模块或已占用端口。
- `Preview → Attached`：确认兼容端口并提交；正式写入配置并启动装配动画。
- `Attached → Unconfigured/Ready/Invalid`：根据配置/权限即时推导，不依赖动画回调。
- `Ready → Disabled → Ready`：禁用/启用；启用时重新运行校验，如条件不满足则转 Unconfigured/Invalid，而非强制 Ready。
- `Attached/Unconfigured/Ready/Disabled/Invalid → Available`：移除并释放占位、清理配置和交互引用。
- 修改参数可能引起 `Ready ↔ Unconfigured/Invalid`，但不得自动卸载工具。

### 4.4 原子性与动画取消

- 同一次确认只提交一次装配，防止连点产生重复实例。
- 状态更新和持久化应在**确定的事务/单次状态更新**完成；动画只是展示已确认的结果。
- 视图切换、改变窗口尺寸、快速移除、减少动态效果、卸载组件和动画被中断，都不得制造幽灵模块、被占用的空端口或错误数据。
- 进场/退场动画需要能取消和清理；被中断时直接同步至当前真实逻辑状态。
- 模块被移除时，Inspector 不得仍指向不存在的实例；选中项应清空或切至合理默认内容。

## 5. 3D Assembly View — 点击自动装配

### 5.1 标准路径

1. 用户在左侧模块架点击 **Add / 添加**。
2. 对应合法端口高亮，核心稍微聚焦；在端口位置出现半透明 **Ghost Preview**；其他端口降低亮度。
3. Inspector 打开模块简介、功能限制与预期目标端口，提供 **Confirm Assembly / 确认装配**、**Cancel / 取消**。
4. 用户确认后，将新模块作为已装配对象写入配置，3D 播放约 **400–800ms** 的机械吸附运动：模块沿可解释曲线靠近接口、锁定，短暂 Cyan 脉冲表示**连接关系建立**，而非模拟 API 请求成功。
5. Inspector 显示结构化配置表单；若尚未授权或字段缺失则为 Unconfigured，不显示 Ready。
6. 保存合法参数/允许读取后进入 Ready；3D 接口和 2D 节点同步改变样式，并显示状态文本。
7. 若用户选择移除，播放逆向脱离/收纳效果，立即正确更新持久化配置，并释放对应接口。

### 5.2 交互优先级

- 核心现有旋转、缩放、点击聚焦应继续可用；进入装配预览时**暂停自动旋转**并减弱摄像机自由操作，防止目标移动。
- 若 Inspector 当前有未提交字段编辑，切换模块时不得静默丢弃用户输入；采用明确的保存/取消策略或字段即改即存，项目内统一一种方式。
- 已装配模块卡片的首要操作应是 **Inspect / 配置**，不是再次 Add。
- 两种工具装配完后，核心仍然具有空间留白和可旋转性，不能被大型平面卡片遮住。

## 6. 3D Assembly View — 可选引导式拖拽

- 支持从左侧模块架按住模块开始拖拽，拖入 3D 中央区域时出现可读的拖拽预览。
- 使用屏幕指针到 3D 交互平面/射线检测的合理映射，只对**预先定义的合法端口**吸附，不实现自由空间任意摆放。
- 拖过兼容端口：高亮端口、显示吸附范围和模块轮廓；松开后触发与点击确认同一套校验及装配逻辑。
- 拖过不兼容端口：局部异常标识 + 明确文字，如“文档读取器不能连接到检索接口”；松开后不提交，模块回到能力架。
- 拖至画布空处、超出工作区或按 `Esc`：取消操作并清理所有幽灵预览。
- 已被其他模块占用的接口不能重复接收；提示已占用。
- 拖拽期间暂停 AZ-CORE 自动旋转；结束后恢复此前状态。既有模型旋转手势和模块拖动手势不得相互抢占。
- 提供拖拽期间可见焦点/目标提示，禁止通过颜色作为唯一兼容性说明。
- **等价访问路径**：键盘和触屏用户通过点击模块、选择端口、确认装配完成全部功能；拖拽只是额外体验，而非完成任务的必经步骤。
- 可复用 2D/HTML 拖拽指示层和 R3F 端口热点；如存在设备命中问题，优先保证点击路径及无障碍，而不是为视觉效果引入不可靠的自由拖拽。

## 7. Inspector — 真实配置、校验与编辑

### 7.1 Inspector 内容

- 模块名称、类型、简短知识解释、所属端口和 **SIMULATED** 说明。
- 当前状态：Available / Preview / Attached / Unconfigured / Ready / Disabled / Invalid，配文字而不只靠颜色。
- 各模块配置字段（见 §3.1），采用真实 `<select>`、`<checkbox>`、按钮等可访问控件；不得只绘制静态图片或假表单。
- 权限说明：仅读取本地模拟资料的教学权限，不是浏览器真实文件访问权限；未授予模拟权限不得进入 Ready。
- 对错误配置的**字段级提示**：具体指出缺少/非法的字段、修复方式。
- 可见且可操作的 Save/Apply（若采用显式保存）、Enable/Disable、Remove 和 Reset Module。
- 介绍型链接/按钮可以打开已有的对应解释面板；尚未做好的知识页明确“后续阶段开放”，不制造假跳转。

### 7.2 同步要求

- 改动 `maxResults`、`readMode`、权限后，切换至 2D System View 再返回，数值完全一致。
- 同一模块只存在一套配置，不因为视图切换复制组件数据。
- Disabled 模块允许查看配置；重新启用必须进行完整校验。
- 不合法参数保存失败时提供原因；已有合法配置不会被局部破坏。

## 8. 2D System View — 从预览变为真实投影

本阶段必须让 M0.1 的二维系统视觉预览成为**可反映实际装配状态的可用视图**，但不开发任意节点编辑器。

- 显示基础 `Model Core` 节点，以及由配置派生的 Search、Reader 节点和连接线；无模块时只保留模型核心。
- 使用同一份 `moduleId` / `portId` / 状态数据决定节点是否存在、标签、连接样式、是否禁用和配置有效性。
- 点击 2D 节点，应同步选中对应模块、展示同一 Inspector 内容；返回 3D 后对应部件仍保持选中（或遵循统一的明确取消规则）。
- 2D 视图允许通过可访问的“添加、配置、禁用、移除”操作编辑**同一份配置**；这些动作切回 3D 后能立即映射为真实的装配结构。
- 连接应有可说明的含义：本阶段表示“已添加工具至模拟研究系统”，不假冒 MCP 连接、实际 API 会话或 Agent 执行事件。
- 对模块尚未配置、已禁用、错误状态有清晰文本和图形差异。
- 切换时镜头和 UI 可以使用简短动效，但不能重新创建另一套独立模型状态。
- 无 WebGL、`prefers-reduced-motion` 或触控设备降级时，2D 模式保留**全部 M0.2 配置能力**。

## 9. 本地持久化、状态恢复与数据安全

- 只保存已确认的持久配置、可选用户偏好和选中视图；**Preview、Dragging、当前动画中间帧不持久化**。
- 推荐 `localStorage` 作为 M0.2 轻量配置存储，不需要 IndexedDB；使用版本号，例如 `schemaVersion: 1` 与命名空间键 `agent-zero:constructor:v1`。
- 启动加载先校验模块 ID、端口 ID、参数取值、权限类型和模式，拒绝未知值；损坏/旧版本数据应优雅降级并给出可恢复方案，不得导致整站白屏。
- 刷新页面后能够复原两种模块的安装、参数、禁用与授权状态；不得误恢复半安装动画。
- 提供 **Reset Constructor / 重置构建器**，有确认步骤，且只清理构建器配置，不删除 M0.1 的开场偏好等其他数据。
- 不依赖网络请求，也不保存凭据、个人敏感数据或真实文件内容。

## 10. 视觉、动效、性能与响应式验收

### 10.1 视觉约束

严格继承 `DESIGN_SYSTEM.md`：Void `#07090D`、Signal `#77D8EC`、Attention `#F0BD78`、Verified `#80D9B4`、Error `#FF8585`；原 AZ-CORE 01 不换形、不换全新风格。

- `PREVIEW`：半透明模块 + 虚线预连接，Amber 高亮目标选择。
- `ASSEMBLING`：机械吸附，运动结束具有清晰的锁定反馈；控制在约 400–800ms。
- `UNCONFIGURED`：Amber 状态提示，保留模块的实体结构。
- `READY`：Cyan 连接线 + Ready 文本，不滥用成功绿色。
- `DISABLED`：结构保留但线路不活跃，并明确显示“Disabled”。
- `INVALID`：Red 局部提示 + 文本原因，不全屏红闪烁。
- `REMOVING`：撤离既有装配位置；移除中重复点击不会触发双重卸载。
- Hover/Press 状态约 150–300ms；非必要镜头切换不阻塞功能。不能用工具调用动画代替装配连接动画。

### 10.2 设备与访问性

- 主要桌面验收视口：1440×900、1920×1080、16:10；另检 1024–1439、768–1023、窄屏小于 768px。
- 桌面左右面板不挤占中央 AZ-CORE 识别空间。窄屏把模块架、Inspector 变成可开合抽屉；不要求手机采用鼠标式精细拖拽。
- Tab / Shift+Tab 可以到达全部关键按钮；Enter/Space 可操作；Esc 可取消预览、拖动或关闭弹层；键盘焦点明显。
- 无障碍标签与状态变化应可读；必要时用适度的 ARIA live 状态反馈，不进行大量连续播报。
- 尊重 `prefers-reduced-motion`：预览/装配可瞬时变更或缩短为简洁淡入，**逻辑结果必须相同**。
- WebGL 不可用/场景报错时必须落到 2D System View，并能完成全部添加、配置、禁用、移除操作。
- 测试快速切换、重复点击、窗口变化后不会出现模型残留、输入失焦、WebGL 资源明显泄漏。

## 11. 工程实施建议（与现有仓库适配，不强制大改目录）

建议将装配领域逻辑从视觉层抽离：

```text
src/
  features/constructor/
    model/                 # module definitions, port registry, config schema
    state/                 # single source of truth, validation, persistence
    actions/               # add, configure, disable, remove; pure transitions
    components/            # module library, inspector, setup forms
    views/                 # 2D System View
  scenes/core/
    ports/                 # 3D visible hotspots & connector anchors
    assembly/              # ghost preview, motion path, connection pulse
  tests/                   # transitions, validation, persistence, UI flows
```

**核心约束**：`validateConnection(moduleId, portId)`、`validateModuleConfig(...)` 等能力应能脱离 Three.js 在普通单元测试中运行。3D 模型不能被当作状态数据库。已有仓库如使用其他合理目录结构，按现状组织，但保持相同分层职责。

状态变化应尽量通过可测试的纯逻辑完成，并清理 GSAP 时间线、Three.js 事件和资源；不要在多个组件中分别写入 `localStorage`，避免状态竞争和数据不一致。

### 11.1 可参考的数据形状（示意，不是强制照抄）

```ts
type ModuleId = 'announcement_search' | 'document_reader';
type PortId = 'SEARCH_PORT' | 'READER_PORT';

type InstalledModule = {
  moduleId: ModuleId;
  portId: PortId;
  enabled: boolean;
  permissions: { read: boolean };
  settings: Record<string, unknown>;
};

type ConstructorConfig = {
  schemaVersion: 1;
  modules: InstalledModule[];
};
```

请在实际代码中使用各模块的**判别联合类型或严格校验 Schema**，而不是一直依赖 `Record<string, unknown>`。示例只是说明标识与权威配置结构的边界。
