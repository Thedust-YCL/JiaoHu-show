## 界面认知与取舍

已建成的学习实验室，当前表面是科研配置工作区。用户从 Constructor 选择模块，配置研究 Agent，检查问题并保存；首要决策是选示例或继续草稿。成功是刷新/加载后参数、3D/2D/Inspector/预检一致。恢复路径为字段默认值、草稿恢复、只恢复损坏的构建器存储。移动端以点击装配和 Inspector 为主。

保留 AZ-CORE 01、色板、布局、装配预览和原生控件；扩展现有代码比替换框架或另起完整页面更能保持历史行为。配置操作与预检渐进展开，避免十类模块表单同时铺开。禁止把模拟说成真实连接、加入虚假评分或泄漏用户文本到 HTML。

## 统一配置契约

Schema v2 延用 modules[].settings（等价于任务书 config），补充 configId/name/description/ISO timestamps、instanceId/moduleType/order、connections、settings。Tools 类包含原有两个稳定 moduleId，因此是十类、最多十一个安装项。Runtime 的设置由根 settings 唯一保存，Inspector 直接编辑它；不维护重复副本。

依赖边根据启用模块及注册表推导，不持久化；显式 connections 存稳定实例引用，禁用/移除时停用/清理引用。只接受有已声明语义的显式边。纯逻辑 Preflight 按固定顺序返回 error/warning/info，所有视图读同一结果。

新存储键 `agent-zero:constructor:v2` 保存当前草稿及具名快照；旧 v1 只读迁移并保留。未知字段/模块保留并警告，危险键拒绝，未来版本/坏结构锁定原始存储直到明确恢复。具名保存与草稿自动恢复区分；删除/覆盖/重置与未保存切换均确认。学习、Journal、Memory Lab、Run 键不写入。

M2.2 入口 `prepareSimulationInput(configuration)` 返回版本化可序列化快照及真实预检；有 error 时 ready=false。Constructor Run 进入预检；已有旧执行实验与报告保持可访问。
