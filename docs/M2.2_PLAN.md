# M2.2 Runtime 实施计划与审计

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans。按任务逐项执行，完成后独立代码审阅。

**Goal:** 让统一 AgentConfiguration 驱动可逐步观察、可审批、可复现的本地模拟。
**Architecture:** 在现有 simulation 分层中增加增量调度能力，复用 createEvent、Search/Reader、evaluateEvidence、Knowledge Lab 检索和 Reliability 护栏。旧 M0 runSimulation 与存储只读兼容，既有报告不迁移重算。Runtime 工作区使用同一配置 store 的不可变快照。
**Tech Stack:** 原生 ES Modules、esbuild、node:test、现有 Chrome CDP 验收。
**Spec:** docs/M2.2_TASK.md（及已完整读取的 PRD、设计系统、M0.1–M2.1）。

## Global Constraints
- 100% 纯前端；无业务后端、真实 AI API、远程搜索、Embedding 或真实 MCP。
- 保留用户未提交改动与旧数据；不主动提交、推送、部署。
- 同一配置、任务数据版本、场景、种子和审批选择可复现；墙钟与 runId 不参与决策。
- 本地模拟、虚构数据、规则与安全局限必须可见；不提前开发 M2.3 比较系统。

## 审计（实施前）
- 配置：configuration.js v2，11 个模块实例覆盖 10 类；settings 是 Runtime 唯一参数来源，Guardrails 审批字段为根 settings 的别名。
- preflight.js 已有依赖、ID、字段、MCP、权限检查；但 modules/connections/settings 容器形状检查不全，prepareSimulationInput 可能放过损坏结构。最小兼容修复：补 error，不删除或改写原始数据。
- Guardrails 缺失时 preflight 仅 warning，Runtime 必须默认拒绝未知/私有权限，不能用 ready 代替每次授权检查。
- 旧执行台一次性 runSimulation 后回放；不具有暂停真实调度或等待审批能力。M1 Runtime Lab 是独立教学实验，不可直接当完整配置引擎。
- 复用：simulation/events/schema.js、serializer.js、tools/*、rules/evidence/*、mission-001、Knowledge Lab chunk/retrieve、Reliability checkInput/checkOutput、统一 knowledge ID。
- 存储：constructor:v2、learning:v2、journal:v1、research:v2 与 legacy execution:v1 独立。M2.2 新建 runtime:v1，最多 5 条，不覆盖上述键。
- 基线：node --test tests/**/*.test.mjs 实际 371 PASS / 0 FAIL（verify/m22/baseline-tests.log）。旧交付报告不视为本轮证据。

## UI cognition / gate
项目为已有功能的学习实验室；用户是理解 Agent 的中文学习者。核心对象是配置、run、step、event、evidence。入口来自构建器预检，首个决策是场景；成功是能解释下一动作与结论边界。恢复路径为修配置、处理审批、重跑；手机主动作是单步与审批。保留 AZ 色板、核心和组件，不增加 landing hero；长日志折叠，明确未执行分支。验证覆盖 CDP 键盘、390px、reduced motion、无 WebGL 与截图。

## Review Focus
- 批准后取消/重复批准不能执行两次工具；每次重跑重新审批。
- 小预算、缺工具、仅摘要和元数据关闭不能从隐藏资料补结论。
- 错误/终态不能继续步进；暂停恢复不能重置重试次数。
- 坏历史与跨 run 引用不能导致静默丢失其他记录或假结果。
- 离开页面/刷新不偷偷继续；历史配置被删除后仍可检查与重跑快照。
