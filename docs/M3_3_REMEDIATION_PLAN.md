# M3.3 发布阻断修复计划

目标：减少静态站首屏不必要的实验代码加载，同时保持离线单文件、既有数据和导航语义；不添加新能力或更改模拟逻辑。

1. 在独立浏览器测试中复现生产包首屏同步加载全部实验，并约束子路径、离线、慢加载下快速切换和加载失败后的可恢复性。
2. 静态站使用 esbuild 动态拆分五个独立 Lab；离线包单独构建并同步内联，保持旧版单文件操作。异步导航提供可见状态，较新的导航或销毁作废过期加载，失败可重试。
3. 比较相同节流条件下首屏资源、ready 时间及 Lab 首次打开，跑真实 dist 的各实验、深链、资源请求和离线版完整回归。不得降低现有测试断言；如 API 变为异步，测试应等待真实加载而不跳过断言。
4. 补充长任务、资源失败和数据兼容验证，更新门禁与交付文档；真机和线上环境没有证据则保留相应阻断。
