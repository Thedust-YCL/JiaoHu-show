## 2. 视觉原则与品牌冻结

沿用既有 `DESIGN_SYSTEM.md`：

-   深色科研终端与精密机械装置的视觉基调。
-   AZ-CORE 01：机械轨道 + 几何核心，辅以少量神经式数据流。
-   电影式开场与专业 2D 控制台结合。
-   Cyan、Amber 等状态色遵循现有语义，不得任意换义。
-   以排版、留白、线框、层级和运动节奏营造精密感，而不是堆叠发光、粒子和装饰。
-   视觉要有沉浸感，信息仍须清楚、可读、可操作。

不允许：

-   改变产品名称、品牌主视觉和核心造型方向。
-   把所有页面统一成相同的大卡片布局。
-   为每个按钮添加持续发光或夸张缩放。
-   添加无意义的扫描线、闪烁、粒子雨、噪声覆盖或背景动效。
-   为营造"高级感"牺牲文字对比度、点击目标大小或信息层级。
-   删除真实功能说明、错误原因或 `SIMULATION / 本地模拟` 标识。

## 3. Design Tokens 与共享组件

先检查现有 CSS Variables、主题系统或 Tailwind
tokens，优先扩展而不是另建。

统一语义包括：

-   背景：全局、面板、抬升面板、浮层。
-   文本：主文本、次文本、辅助文本、禁用文本。
-   状态：default、hover、focus、active、disabled、loading、success、warning、error。
-   线条：默认边框、弱分隔线、强调边框、焦点轮廓。
-   空间：页面边距、区块间距、组件间距、紧凑/标准/宽松密度。
-   圆角、阴影、发光强度、层级与 z-index。
-   排版：字体栈、字号、字重、行高、字距、数字和代码文本。
-   动效：时长、缓动、进入/退出位移和减少动效规则。
-   断点：依据实际布局审计定义，不让各页面独立发明断点。

优先统一高频组件：

-   Primary / Secondary / Ghost / Destructive Button。
-   Icon Button、Tooltip、Badge、Status Indicator。
-   Panel、Section Header、Divider。
-   Input、Textarea、Select、Checkbox、Toggle。
-   Dialog、Drawer、Popover。
-   Toast、Inline Alert、Validation Message。
-   Loading、Skeleton、Empty State、Error State。
-   Breadcrumb、Tabs、Segmented Control。
-   Code、Event、Evidence、Citation 展示。

相同语义允许明确的 variants，但不得通过大量临时 CSS
变体造成设计系统碎片化。所有控件必须有真实行为，装饰元素不得伪装成按钮。

## 4. Cinematic Intro 与空间运镜

### 体验目标

开场应让用户感到进入一个精密 AI
研究系统，而不是等待一段与产品无关的片头。

建议节奏：

1.  环境建立：简洁空间背景与低强度数据迹线。
2.  核心显现：AZ-CORE 01 机械轨道与几何核心进入焦点。
3.  系统唤醒：以少量状态线索表达模块待命，不展示伪造的真实网络连接。
4.  标题与主操作出现：清楚呈现进入知识宇宙/控制台的下一步。
5.  进入主界面：镜头与 UI 过渡自然，不长时间阻止操作。

实际时长以现有实现和体验测试为准，不强制照搬固定秒数。

### 交互要求

-   用户可跳过开场或直接进入主界面。
-   深层链接、页面刷新或从知识详情返回时，不得错误地重新锁死在开场。
-   根据现有产品决策，避免重复访问时强制播放完整片头。
-   支持
    `prefers-reduced-motion`：缩短运动、淡入或静态替代，不改变功能路径。
-   动画失败、WebGL 不可用或资源加载失败时，仍能进入可用界面。
-   运镜服务于聚焦与过渡；粒子、数据流和发光强度保持克制。
-   不让装饰动画覆盖按钮、表单、图谱节点和运行日志。
-   核心装配状态必须由真实配置状态驱动。

## 5. AZ-CORE 01 与 3D 体验打磨

保留机械轨道 +
几何核心的冻结设计。只修复材质、层级、状态反馈、过渡、可读性及与 2D
控制台的联动问题。

至少审计状态映射：

-   Idle / Standby。
-   Module Installed / Disabled。
-   Configuration Warning / Error。
-   Preflight Passed / Blocked。
-   Runtime Running / Paused / Waiting Approval。
-   Runtime Completed / Failed / Cancelled。
-   A/B Comparison Selected / Active（如现有设计需要）。

要求：

-   状态颜色、动画和文字说明一致；不能只靠 3D 发光提示状态。
-   点击模块或关联视图时，选中状态与 Inspector 同步。
-   安装/移除模块后，核心状态正确更新。
-   Runtime 状态变化只表现真实事件，不提前播放未发生的步骤。
-   A/B 模式切换时，明确当前展示哪一侧配置。
-   动画中断或页面切换后，状态能从数据模型正确恢复。
-   WebGL 不可用或初始化失败时，显示降级提示，并保留 2D System
    View、配置、运行和实验对比能力。
-   不无限重试 3D 初始化，不让 3D 错误导致全站崩溃。

## 6. 全站导航与页面过渡

审计实际存在的核心区域：

-   Cinematic Intro / Entry。
-   Story / 六大知识章节。
-   Atlas / Knowledge Detail。
-   六个 Lab / 交互实验。
-   Agent Constructor。
-   Runtime / Execution Inspector。
-   A/B Comparison。
-   Knowledge Journal / 学习记录。
-   Research Report / Citation View。
-   全局导航、帮助、设置和弹窗（以仓库实际实现为准）。

要求：

-   当前导航项、路由和页面内容一致。
-   直接打开深层链接时页面正确初始化。
-   浏览器返回/前进不导致状态错乱或重复提交。
-   从知识详情返回时，尽可能恢复图谱视图、选中节点和滚动位置。
-   从 Runtime 进入证据详情后，可以回到原运行事件。
-   从 A/B 对比跳转到某侧配置/事件时，保留 A/B 上下文。
-   弹窗关闭后焦点返回触发它的控件。
-   未保存配置或未完成操作不能被导航静默丢弃。
-   页面过渡短而明确，不强制长时间全屏动画。
-   减少动效模式下仍能清晰理解页面变化。

## 7. Lab、Constructor、Runtime 与 Comparison 一致性

相同语义的操作尽量保持一致：

-   Add / Install：添加模块或能力。
-   Remove：移除。
-   Enable / Disable：启用或禁用。
-   Save：保存配置。
-   Run / Step：连续运行/单步执行。
-   Pause / Resume / Cancel：暂停/继续/取消。
-   Retry：仅用于确实可重试的操作。
-   Reset：明确重置范围。
-   Compare：明确 A/B 两侧。
-   Export：说明导出内容和格式。

要求：

-   操作被接受时及时显示状态变化。
-   失败时显示可理解原因与可行操作。
-   等待审批时突出显示待处理内容。
-   运行结束时区分 completed、failed、cancelled。
-   证据不足、来源冲突和权限拒绝不得被显示成普通成功。
-   模拟运行始终保留 `SIMULATION / 本地模拟` 说明。
-   配置仍由 M2.1 的统一 schema 管理。
-   Runtime 事件与运行快照仍由 M2.2 逻辑产生。
-   A/B 指标仍由 M2.3 的实际记录计算。
-   Knowledge Journal、学习进度、配置和运行历史保持隔离。
-   不通过静态假数据填满界面。

## 8. 响应式与多端体验

桌面端优先，但平板与窄屏仍须完成关键任务。不要只缩小桌面三栏。

### 桌面端

-   保留 3D 核心 + 2D 专业控制台组合。
-   模块目录、主工作区、Inspector 可合理折叠或调整宽度。
-   关键按钮、错误提示不被固定面板遮挡。
-   宽屏内容不应过度拉伸。

### 平板端

-   Inspector 可改为侧边抽屉或独立面板。
-   图谱、运行时间线和 A/B 对比可操作。
-   触控目标与滚动行为清晰。
-   关键内容不依赖 hover 才可查看。

### 窄屏端

-   三栏改为标签页、抽屉或纵向布局。
-   3D 核心可缩小或用简化静态展示，但不能挤掉关键控制。
-   Atlas 提供可搜索/可键盘操作的列表入口，不只依赖拖拽图谱。
-   A/B 对比允许切换 A/B 与查看差异摘要，不强行压缩成不可读双栏。
-   Runtime 的步骤、审批、错误和结果仍可访问。
-   表格可横向滚动或转为结构化卡片，不得丢失关键字段。
-   表单和弹窗在常见窄屏视口中可访问。

### 至少检查的视口

-   桌面：1366×768、1440×900 或项目主要支持的近似尺寸。
-   平板：约 768--1024 CSS px 宽。
-   窄屏：约 360--430 CSS px 宽。

报告中记录实际测试尺寸和浏览器。不得声称在真实设备测试，除非确实执行。

## 9. Loading、Empty、Error 与 Success 状态

对关键流程建立一致状态：

-   初次加载、本地数据尚未初始化。
-   无搜索结果、无模块、无配置、无运行记录。
-   配置校验失败、本地存储不可用或数据损坏。
-   WebGL 初始化失败。
-   运行失败、取消或等待审批。
-   引用资料缺失。
-   导出失败或浏览器不支持相关操作。
-   保存成功、配置更新、实验保存成功。

要求：

-   Empty State 说明为什么为空，并给出合理下一步。
-   Error State 在可知范围内说明实际原因，不只显示泛化错误。
-   Retry 只出现在确实可重试的操作上。
-   Success 反馈简洁，不持续占据屏幕。
-   Loading 不得无限旋转；可取消的操作提供取消入口。
-   本地存储错误不能自动清空所有数据。
-   模拟任务中的真实失败分支应保留为实验结果，不能被全局错误 UI 覆盖。

## 10. 文案、术语与内容呈现

检查并统一术语：Agent、Model、Tool、MCP、Skill、Memory、Context、Retrieval、RAG、Evidence、Workflow、Agent
Loop、Runtime、Guardrails、Permission、Approval、Run、Step、Branch、Retry、Preflight、Configuration、Experiment、Comparison、Archive。

要求：

-   以清晰中文解释关键动作，保留必要英文专业词。
-   错误文案说明问题与下一步。
-   危险操作说明影响范围。
-   模拟边界清楚，但不重复刷屏。
-   不夸大准确率、智能程度或真实联网能力。
-   不用无意义的全大写与过度技术缩写。
-   知识条目若仍为 draft 或不完整，应如实呈现。
-   不为视觉一致隐藏来源、证据不足或引用不完整。
-   代码、日志、引用 ID 和数字使用适合阅读的排版。

## 11. Accessibility 与减少动态效果

审计并改善：

-   键盘可达性：导航、弹窗、表单、图谱替代视图、运行控制、审批、导出。
-   `:focus-visible` 清晰且不被背景或发光吞没。
-   图标按钮、状态指示、表单错误有可访问名称。
-   弹窗打开后进入合理焦点，关闭后返回触发控件。
-   运行状态、保存结果、错误和审批等待可被辅助技术感知。
-   错误/警告/完成不只通过颜色表达。
-   检查小字、弱化标签、发光文本和禁用状态的可读性。
-   `prefers-reduced-motion` 减少视差、缩放、粒子和长距离运动。
-   Atlas 提供可搜索/可键盘访问的节点列表。
-   3D 核心状态有文字或 2D 替代信息。
-   表单错误与对应输入明确关联。
-   避免频繁动画或自动更新干扰阅读。

不要求本阶段宣称达到所有正式认证标准，但必须记录可验证改进与遗留问题。

## 12. 性能纪律与 M3.2 边界

M3.1 可以修复明显影响体验的性能问题，但不做完整性能专项。

必须避免：

-   引入明显更重的依赖来实现轻微装饰。
-   每次状态变化都无条件重建 3D 场景。
-   动画循环更新不相关的 UI 状态。
-   隐藏面板持续执行不必要动画。
-   大型 3D 场景成为所有窄屏状态的唯一内容。

以下留给 M3.2：

-   全站性能剖析与性能预算。
-   3D 资源、纹理、粒子和渲染管线深度优化。
-   包体积、分包、缓存与加载策略专项。
-   大规模自动化质量测试和浏览器兼容性矩阵。
-   发布前全面安全与数据边界审计。

## 15. 自动化与人工验收最低范围

### 自动化

-   共享组件 variants 与关键状态渲染测试。
-   导航、深层链接、返回和未保存修改保护。
-   3D 状态映射与 2D/Inspector 一致性。
-   Constructor、Runtime、A/B Comparison 的关键操作回归。
-   Loading、Empty、Error、Success 状态测试。
-   响应式下关键组件可见性与交互测试（按项目工具能力）。
-   键盘焦点与弹窗交互测试。
-   `prefers-reduced-motion` 下关键操作仍可用。
-   本地模拟标识、证据状态和权限反馈未被隐藏。
-   静态构建与纯前端约束检查。

### 人工检查

-   开场是否有节奏但不拖沓。
-   AZ-CORE 01 是否仍是视觉中心。
-   页面是否像同一产品，同时保留各自信息结构。
-   窄屏是否能真正完成关键任务。
-   错误、证据不足、权限拒绝是否清晰。
-   减少动效后是否仍能理解状态。
-   主要交互是否有真实反馈。

报告中区分自动化测试、人工检查与未测试项目。
