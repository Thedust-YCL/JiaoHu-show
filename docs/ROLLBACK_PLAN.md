# 静态发布回滚与数据恢复方案

当前实际 Pages 来源、线上 URL 和上一个稳定部署均未确认，回滚尚未演练。发布前由项目维护者记录部署方式、候选提交和前一稳定提交或完整静态产物、资产摘要、站点 URL，以及浏览器数据 schema 与兼容测试结果。先保存当前代码和构建，不重置或覆盖现有工作树。

出现 404、资源不匹配、核心流程回归或数据兼容故障时，记录 URL、时间、部署 ID、控制台和失败请求；停止继续发布。得到相应授权后，按实际 Pages 发布机制重新部署已保存的完整稳定产物或稳定提交，保持 HTML、入口 JS、CSS 和全部代码块同一版本；不要猜测仓库分支或强推。旧页面可能仍引用旧版本的按需代码块，须预先验证旧资源保留或明确恢复流程，不能假设替换站点后所有已打开页面立即更新。等待部署完成，在新会话及普通会话验证资源、Hash 深链、刷新、关键旅程和缓存版本；必要时检查 CDN 缓存失效状态。记录恢复时间及结果。

浏览器数据不会随静态站点自动回滚。用隔离浏览器 profile 和复制的测试夹具验证旧版读取新版配置、Runtime 和实验档案；在兼容性未经验证前禁止宣称可安全降级。遇到损坏或未知 schema 时保留原始记录，优先使用应用提供的备份或导出；不要以清空 localStorage、IndexedDB 或全部站点数据作为快捷修复。兼容失败时维持阻断，制定并验证非破坏性恢复方案。
