## 3. M0.3 用户体验 Golden Slice

**短闭环 A — 从知识到系统**

1. 在 Hub 点击 `ATLAS`，进入仍然延续 AZ-DESIGN 的深空知识星图。
2. 搜索 `Tool Calling`，画布自动定位到该节点、突出直接关联线并打开摘要。
3. 点击 `LEARN / 学习` 进入完整 Tool Calling 页面，切换 `UNDERSTAND` 与 `INSPECT`，操作内嵌的请求 → 工具执行 → 响应小实验。
4. 点击 `VIEW IN CONSTRUCTOR / 在系统中查看`，返回现有构建器，定位 `announcement_search` 或 `document_reader`；若尚未装配，只定位能力架并说明“尚未装配”，**不私自添加模块或授予权限**。
5. 用户完成 M0.2 的 Search/Reader 配置，确认运行条件后进入 `RUN SIMULATION`。

**短闭环 B — 从装配到运行**

1. 使用现有 M0.2 持久配置作为模拟输入快照，显示当前可用的工具和必要模拟权限。
2. 选择 M0.3 内置样本研究任务（虚构大学公告资料读取），启动浏览器本地模拟。
3. 同一配置在相同数据版本下输出同一条事件轨迹；若工具缺失、禁用或无权限，轨迹必须反映真实原因。
4. Execution 画面随当前事件显示高亮模块、活动数据流、分支路径；事件 Inspector 展示该步输入/输出、规则和资料引用。
5. 用户暂停、逐事件前进/后退或选择任一事件，3D/2D/Inspector 应同时定位到相同的 `eventId`。
6. 返回 Constructor 修改参数或禁用 Reader，再次运行，应该看到**有因果关联**的不同事件，不只是换了颜色的同一段动画。

## 4. Atlas：10 个可用知识节点

### 4.1 首期节点词表（固定 10 个）

| conceptId | 显示名 | 本轮解释焦点 | 对应系统定位 |
|---|---|---|---|
| `llm` | LLM | 负责语言生成和工具调用请求的模型能力 | Core |
| `agent` | Agent | 模型与工具、控制流程共同组成可执行任务的系统 | Core/Runtime 概念 |
| `tool_calling` | Tool Calling | 模型提出调用请求、外部执行环境执行工具再返回结果 | Search / Reader |
| `tools` | Tools | 提供特定外部能力的可调用接口；不等同于协议 | Search / Reader |
| `api` | API | 软件能力暴露与调用的接口概念 | 解释性节点 |
| `mcp` | MCP | 标准化连接协议；工具无需一律通过 MCP | 解释性节点，不触发真实连接 |
| `skills` | Skills | 可按需加载的任务说明及关联资源；并非工具本身 | 解释性节点，暂无装配模块 |
| `rag` | RAG | 检索增强生成；不等于记忆或关键词搜索 | 解释性节点，实验后续开放 |
| `workflow` | Workflow | 开发者定义执行路径的工作流 | 解释性节点，A/B 后续开放 |
| `harness` | Harness | 包围模型的工具协调、上下文与运行控制环境 | 解释性节点，后续扩展 |

**重要**：M0.3 的其他 9 个节点须包含：一句话定义、2–3 段经过审校的简明解释、至少一个常见误解、相关概念入口和后续学习提示；**只有 `tool_calling` 必须拥有完整分层知识页和可操作实验**。不得把其他九个都伪装成内容已完成的全尺寸实验室。

### 4.2 连线关系：数据决定，不靠随机算法臆造

首期语义关系应经过人工明确配置，举例：

| source → target | 关系 | 解释要求 |
|---|---|---|
| `agent → llm` | `USES` | Agent 系统通常可使用模型完成判断或生成任务相关内容 |
| `agent → tools` | `USES` | Agent 可调用外部工具以完成任务 |
| `llm → tool_calling` | `RELATED` | 支持工具调用的模型可生成结构化工具请求；真正执行在外部 |
| `tool_calling → tools` | `USES` | 工具调用机制请求执行已提供的工具 |
| `tools → api` | `RELATED` | 部分工具可封装 API，但二者不是同义词 |
| `mcp → tools` | `RELATED` | MCP Server 可暴露工具，也可暴露其他能力 |
| `agent → skills` | `RELATED` | Agent 可按需加载任务技能说明，不等于授予工具权限 |
| `agent → rag` | `RELATED` | 检索增强是可选机制，并非所有 Agent 都使用 |
| `workflow → agent` | `CONTRASTS` | 解释预设流程与运行期动态选择的区别，避免绝对化 |
| `harness → agent` | `RELATED` | Harness 负责支持或组织 Agent 的执行环境，不是另一个模型 |

- 关系类型统一为 `USES`、`PART_OF`、`RELATED`、`CONTRASTS`。本轮**不强求每类都有实例**，杜绝为填满连线样式而编造 PART_OF 关系；后续审核确认时再引入。
- 每条边必须有 `id`、`sourceId`、`targetId`、`type`、`description`、可选有向性标记。用户悬停/选中能看到说明；不要让线条仅用于制造复杂效果。
- 如 UI 使用方向箭头，仅对明确有向语义的边显示。RELATED/CONTRASTS 不应默认为严格单向因果。

### 4.3 图谱操作

- 点击节点：选中、打开短解释；双击或聚焦按钮：移动/缩放到该节点。
- 搜索：中英文别名、大小写、部分匹配；空结果有“没有找到相关概念”，清除恢复全图。
- 支持画布平移、合理限幅缩放、`Reset View / 复位`、适配视窗尺寸。
- 桌面鼠标/触控板和触屏可操作；提供 HTML 概念列表或可访问的搜索结果，使键盘用户无需操作 3D/Canvas 命中点也能选择节点。
- 节点细节保留 `Learn`、`Related`、`View in Constructor`（能关联的节点才显示）和 `Back to Hub`。
- 图谱可以采用 **SVG/Canvas + 轻空间深度效果**，不强制所有节点为复杂 3D mesh；应优先保证读得清、找得到、状态可解释。
- 图谱布局优先使用**固定/可重现坐标**或具种子的布局；不能每次刷新随机重排、造成学习导航失忆。
- 未完成的概念实验只显示已开放的简介和 `Coming in later phase`，无假按钮。

## 5. Tool Calling：首个完整知识节点

### 5.1 内容结构（四步学习路径）

| 步骤 | 内容 | 用户能做什么 |
|---|---|---|
| DISCOVER | “为什么模型不能直接知道虚构校园公告？” | 观察没有外部数据时的能力限制 |
| UNDERSTAND | “请求、执行、返回”三方职责 | 点击/逐步观察 Tool Call 流程 |
| EXPERIMENT | 用本地示例运行一次 Tool Calling | 更换输入参数、查看成功与失败说明 |
| CONNECT | 展示 LLM、Tools、API、MCP、Agent 的关系 | 跳至关联概念与现有构建器工具 |

### 5.2 UNDERSTAND 与 INSPECT 两个深度层

**UNDERSTAND / 入门**

- 一句话：**Tool Calling 让模型可以请求调用外部工具，实际执行通常由外部应用/运行环境完成，再将结果交还模型处理。**
- 可视化分出三段：模型提出调用请求 → 执行环境检查并调用本地模拟工具 → 模拟结果返回任务上下文。
- 不宣称每个模型都支持 Tool Calling，也不把模型内部推理过程当成可观察的真实轨迹。

**INSPECT / 深入**

- 结构化 JSON 为**简化示意格式**，例如 `{ "tool": "announcement_search", "arguments": { "scope": "campus_events", "maxResults": 3 } }`。
- 显示请求参数、工具注册与可用性、执行侧权限校验、模拟工具结果和返回后的事件记录。
- 明确区分：Tool Calling / API / MCP / Skills / Agent；工具可以不经 MCP 提供，Skills 不会自动执行 API。
- 展示常见误解：模型自带实时互联网、MCP 就是 Agent、能输出工具 JSON 就意味着外部工具已经执行成功。

### 5.3 内嵌实验交互

- 支持 `step`, `play`, `reset`，允许查看模拟成功与“工具未开放/权限不足”的分支；至少有一项参数（如搜索范围）会改变本地预设请求与响应。
- 必须与全站共享教学工具定义及数据类型，避免 Tool Calling 页面写了一套与 Constructor 完全不一样的工具参数模型。
- 允许在教学页独立运行一条固定演示轨迹，但必须明确显示“这是知识示范，不会修改当前构建器配置”。
- “在 Constructor 查看”通过路由/状态参数定位实际工具实例或能力架；不向全局 store 写入虚构已装配项。

## 6. M0.3 本地教学研究样本（最小版）

### 6.1 数据包约束

- 新建 `mission-001-mini` 等版本化数据包：**虚构大学的校园公告搜索与读取**。M0.3 只需要 2–3 份公告，包含标题、正文、来源、发布日期、可用检索标签与稳定 ID。
- 每条记录包含 `sourceId`、`chunkId`（可采用单片段）、`publishedAt`、`isFictional: true`、`content` 等字段，明确标注模拟数据。
- 为 M0.4 预留 `supersedes`、`citation`、`validity` 等字段；**本阶段不实现正式资料冲突与更正判断**。
- 文档可描述类似“校园创客分享会”“社团招新咨询”，保持虚构性和教学目的；数据本身应自洽，不引入无法验证的真实学校公告。
- `searchScope`、`maxResults`、`readMode`、`includeMetadata` 等来自 M0.2 的既有配置，必须在模拟工具中实际生效，不允许表面上存在却从不影响事件/响应。
- 对 `readMode=summary`：只能返回预先定义的摘要，不能发出 `full_text_read` 事件，也不能声称拿到了全文；`readMode=full_text` 才能返回完整内容。
- `includeMetadata=false` 时，不应在工具返回的公开数据中悄悄补回已被关闭的元数据；事件仍可保留运行引擎必需的内部 sourceId，以用于调试，但要区分内部追踪元数据与用户可见的模拟工具响应。
- 数据与规则必须是源码仓库内可读的本地文件；不需要后端数据库或运行时下载远程数据。

### 6.2 两个本地模拟工具

**`announcement_search`**
- 输入：`searchScope`、`maxResults`、预置查询关键词。
- 输出：符合范围且排序稳定的公告搜索结果（`sourceId`、标题、可见摘要等）。
- 缺少模块、禁用、状态非 Ready 或模拟读权限未授权：不得返回“成功检索”。
- `maxResults` 要截断结果并在事件详情中显示实际数量。若本地数据少于上限，显示真实较小数量而不是编造返回数。

**`document_reader`**
- 输入：来自搜索结果的合法 `sourceId`，以及 `readMode`、`includeMetadata`。
- 输出：本地可读正文或摘要、可选发布日期/来源等元数据。
- 当搜索无结果时不调用 Reader；当 Reader 不存在/不 Ready 时不输出正文已读取事件。
- 即使用户构建器里允许两种工具同时存在，也不能当成所有研究步骤都必须成功。

### 6.3 必需执行分支（本轮四条）

| 场景 | 条件 | 必须生成的可观察结果 |
|---|---|---|
| B01 正常 | Search Ready 且 Reader Ready | 接收任务 → 检索 → 读取 → 记录样本资料 → 简要阶段完成；明确尚未生成报告 |
| B02 缺 Search | Search 未安装/Disabled/未授权/无效 | 输入校验/不可用事件 → 信息不足的结束状态；**没有成功的搜索或读取事件** |
| B03 缺 Reader | Search Ready 但 Reader 不可用 | 有真实的模拟搜索结果 → Reader 不可用的阻断/降级事件 → 以摘要级资料结束；**没有已读全文事件** |
| B04 模拟超时 | 用户显式开启 M0.3 的 `faultMode=search_timeout` 测试条件 | 搜索请求 → 确定性超时事件 → 结束或降级，不伪造成功响应；正式重试/回退策略留给 M0.4 |

B04 的故障注入是**本次运行设置**，不得误写成 M0.2 工具的永久 Invalid，也不能不加提示随机触发。

**参数效应要求**：至少验证 `searchScope` 影响搜索候选、`maxResults` 限制返回数、`readMode` 改变读取内容范围、`includeMetadata` 改变用户可见工具响应。构建器配置不得被模拟器改写。

## 7. 模拟引擎：输入、事件、分支、可复现性

### 7.1 必须遵守的职责边界

1. **权威配置**：读取 M0.2 已确认并通过现有 schema 校验的配置对象（运行开始时冻结深拷贝或不可变快照）；不要另建一套 “runtimeSearchEnabled” 等独立业务开关。
2. **任务数据**：通过稳定 ID 和版本读取 `mission-001-mini`。
3. **纯逻辑引擎**：`runSimulation(configSnapshot, missionData, runOptions)` → 结构化不可变结果；内部不引用 DOM、Canvas、Three.js、摄像机、动画帧或 React hook。
4. **事件结果**：包含事件序列、运行结局、产生结果所需的追踪信息；视觉层仅订阅事件。
5. **回放控制**：在已生成的事件数组上改变当前事件指针，不再运行一遍模拟逻辑。
6. **现场配置更改**：回放期间修改 Constructor 仅更新下次运行用的配置，不能悄悄重写已有历史轨迹；新运行使用新快照。

### 7.2 推荐的类型边界（适配现有代码，不强制逐字采用）

```ts
// 使用 M0.2 已确认配置类型，而不是另写一个并行的影子 store。
type SimulationInput = {
  missionId: 'mission-001-mini';
  missionVersion: number;
  constructorSnapshot: ConstructorConfig;
  faultMode: 'normal' | 'search_timeout';
};

type ExecutionEvent = {
  id: string;                 // 稳定，不依赖 Date.now() / Math.random()
  sequence: number;
  phase: 'VALIDATION' | 'PLAN' | 'SEARCH' | 'READ' | 'EVIDENCE' | 'END';
  type: string;               // e.g. tool.call / tool.result / tool.error / validation.blocked
  status: 'started' | 'success' | 'blocked' | 'error' | 'info';
  actorId: 'system' | 'model_core' | 'announcement_search' | 'document_reader';
  toolId?: 'announcement_search' | 'document_reader';
  inputRef?: string;
  outputRef?: string;
  sourceIds?: string[];
  chunkIds?: string[];
  branchId?: string;          // 指向分支规则
  ruleId?: string;            // 导致事件的逻辑规则
  message: string;            // 面向用户的短解释
};

type SimulationRun = {
  schemaVersion: number;
  runId: string;
  missionId: string;
  missionVersion: number;
  configSnapshot: ConstructorConfig;
  options: { faultMode: 'normal' | 'search_timeout' };
  outcome: 'sample_acquired' | 'partial' | 'blocked' | 'error';
  events: ExecutionEvent[];
  artifacts: Record<string, unknown>; // 仅本地响应摘要/样本资料；不等于正式报告
};
```

- 事件中的 `inputRef`、`outputRef` 可以指向当前 Run 内的安全载荷字典，不强制每条事件复制完整正文。引用必须能在运行快照内解析，不依赖现有 Constructor 之后是否被修改。
- `runId` 可用本地递增序号或由配置/数据 hash 派生的稳定 ID；重现性比名字形式重要。不能使用当前时间造成与输入无关的事件差异，若记录实际创建时间则单独存非语义元数据。
- `sourceId`、`chunkId` 在 M0.3 可用于事件详情中的资料定位；**此处尚不构成 M0.4 的完整报告引用溯源**。
- 如果实际工程已有类似事件类型，优先扩展原类型并采用版本化迁移；不要制造第二套相互矛盾的执行事件模型。

### 7.3 运行事件基础顺序

最小成功运行示例：

```text
00 run.started
01 config.validated
02 task.plan_created             (演示用固定简化规划，非真实模型推理)
03 tool.call: announcement_search
04 tool.result: announcement_search
05 tool.call: document_reader
06 tool.result: document_reader
07 evidence.sample_collected     (仅样本资料已取得，并非真实性核验)
08 run.completed                 (本阶段不生成报告)
```

- 禁止用“AI 正在深度思考”“来源已验证”等与实际本地规则不符的描述。
- 结果事件必须与真实 M0.2 状态一致：未安装、未授权或 Disabled 工具不能被暗中调用成功。
- 工具错误为单次运行事件，不能把模块永久写成 `Invalid`。
- `RUN` 前若用户配置不满足要求，可允许产生一次可解释的 blocked Run，以用于教学对比；不要单纯把按钮禁用导致用户永远看不到缺工具路径。

### 7.4 确定性测试

- 固定 `constructorSnapshot + missionId + missionVersion + faultMode`，其事件内容、顺序、分支与 outcome 必须相同。
- 对结果做快照/纯函数测试；若 UI 为演示播放添加视觉延迟，不应改变事件数组。
- 事件回放速度变化、Tab 切换、WebGL 降级不能改变 `SimulationRun` 数据。
- 简单防护：未知工具 ID、损坏的配置版本、未知资料 ID、恶意/异常长文本的显示须安全降级；React 文本默认转义，不将文档正文作为不安全 HTML 注入。

## 8. Execution Workspace / Replay

### 8.1 桌面布局与视觉设计

沿用 `DESIGN_SYSTEM.md` 的 Void 黑、精密描边、Signal Cyan、Attention Amber、Error Red：

```text
┌──────────────────────────────────────────────────────────────────────┐
│ A/0  EXECUTION / MISSION-001-MINI       SIMULATED · VIEW: 3D / 2D  │
├────────────────────────┬───────────────────────────┬────────────────┤
│ EXECUTION GRAPH        │  AZ-CORE 01               │ EVENT INSPECTOR│
│ 本次实际走过的事件路径  │  工具请求/返回的联动可视化 │ 输入/输出/原因 │
│ 选择任一事件定位       │  可旋转、可选中工具         │ 引用/资料 ID   │
├────────────────────────┴───────────────────────────┴────────────────┤
│  EVENT TIMELINE     [上一事件] [播放/暂停] [下一事件] [速度] [复位]  │
└──────────────────────────────────────────────────────────────────────┘
```

这只是信息架构示意：如果现有 UI 结构更合理，可以调整位置，但**左侧实际事件路径、中央事件可视化、右侧 Inspector、底部可操作时间轴**的职责不可丢失。

### 8.2 必需回放操作

- `Play/Pause`：播放/暂停已生成事件序列；播放到尾端显示 `Completed / Blocked / Error` 等真实 outcome。
- `Previous/Next Event`：逐个事件跳转，包括异常事件；首尾边界不会越界。
- `Seek`：从事件条/列表选择任意序号，三处视图同步到同一事件。
- `Speed`：提供 0.5×、1×、2×、4×；只影响事件展示与脉冲动效的视觉速度，不影响模拟规则。
- `Restart Replay`：把指针归零，**不重新调用引擎**；`New Run` 才使用当前 Constructor 配置生成新轨迹。
- 回放暂停后，数据流/执行脉冲暂停；允许查看旧事件的静态内容和旋转观察核心。镜头待机机械旋转可按减少动态偏好停止。
- 切页/关闭弹层/组件卸载时清理动画、事件监听和播放调度，不能发生事件指针失控或重复播放；播放过程中允许手动 Seek。

### 8.3 图与 Inspector 的真实含义

- **Knowledge Graph** 只存 AI 概念关系，不因运行失败变更连线。
- **System Graph** 只投影已装配的工具与逻辑连接，不把运行成功作为“模块刚刚被安装”的证据。
- **Execution Graph** 只显示本次 `SimulationRun.events` 经过的阶段和分支；不把预设的全部可能分支都画成“实际走过”。允许用虚线显示未走过的候选分支，但必须标注未执行。
- `eventId` 是三个执行观察区的同步锚点。选择 Reader 工具调用事件时，AZ-CORE 对应 Reader 轨道高亮，2D 执行路径聚焦 Reader，Inspector 显示同一事件；选择验证阻断事件时不得亮起 Reader 成功状态。
- Inspector 至少显示：序号、事件类型、可读短说明、状态、参与者、输入/输出（允许折叠）、工具 ID、资料引用、触发分支/规则说明。
- 数据流 Cyan 表示**当前演示模拟请求/响应**，不能把已装配的稳态连接误画成正在联网访问。
- WebGL 降级时，2D Execution Graph + Inspector + Timeline 提供等价的结果理解，不丢掉核心教学信息。

### 8.4 运行历史与本地持久化

- M0.3 最低要求保存**最近一次完整 Run**：输入配置快照、任务数据版本、事件、outcome、显示需要的安全载荷。
- M0.2 的 `agent-zero:constructor:v1` 或项目当前实际配置键仍由 Constructor 独立管理；不要由 Execution 重写、覆盖或清理。
- 建议历史键 `agent-zero:execution:v1`，或按现有仓库命名空间约定命名；含 `schemaVersion`、对旧/坏数据的解析与清理策略。
- M0.3 不强制完整 Run 列表、复杂 IndexedDB 数据仓库、云端同步；如果本地记录体积明显变大，可单独使用 IndexedDB，但保持静态前端。
- 清理单次运行记录不清除已装配模块、开场偏好或学习进度。输出含虚构资料且不含真实用户个人数据、API Key。

## 9. 学习进度与跨视图联动

- 维护单独的概念学习状态：`unexplored`、`exploring`、`experiment_completed`、`related_discovered`（可用多个标志组合，避免单枚举丢失信息）。
- Atlas/Tool Calling 页面共用 `conceptId`，访问标记探索中，完成 Tool Calling 核心交互后可标记实验完成；**不是学习测验成绩**。
- 进度使用独立命名空间持久化，如 `agent-zero:learning:v1`；不写入 Constructor 模块配置，也不影响引擎分支。
- 相关概念选择可从 Atlas 进入 Tool Calling，再回到先前视图和选中节点；`Back to Hub` 永远可达。
- Tool Calling 页面 `View in Constructor` 应对尚未安装的 Search/Reader 做定位和说明，不直接修改权限或启用状态。
- 从 Constructor 中选择已装配工具，可点击学习链接返回 Tool Calling 知识节点，随后能回到原始 Inspector 上下文。
- 用户在 Atlas 搜索概念或展开知识页时，不得触发模拟 Run 或清空运行轨迹。

## 10. 视觉、交互、响应式与无障碍

- 严格继承 AZ-DESIGN v1：机械轨道 + 黑曜多面体 + 少量事件数据流，避免满屏随机发光节点。知识图谱使用与 Control Hub 一致的边框、背景、字号、冷色信号与状态语义。
- Atlas 背景可采用少量静态星点/网格建立深度，但节点/连线的首要目标是语义可读与可操作；不要把 `A/0` 标志换成新品牌。
- Tool Calling 动态流程建议使用可复用连线、数据包和分阶段高亮；特效由当前教学步骤决定，不靠循环时间随机切换。
- Execution 回放时仅突出当前事件相关的模块与链路；非相关装饰运动降低；Paused 静止、错误局部 Fracture、重置则回到确定状态。
- 动画速度约束：微交互 150–300ms，显著场景转场 1–2s，但必须可中断。事件可见持续时间可以独立设置，不把视觉延迟写成业务规则。
- 屏幕 1440×900、1920×1080、16:10；窄屏 Inspector 可折叠，移动端采用 2D 图+底部抽屉+可访问事件列表，不强制拖拽和复杂空间手势。
- `prefers-reduced-motion` 时，用静态阶段高亮代替频繁飞行脉冲；功能、模拟事件与回放控制仍完整。
- 可用键盘导航 Atlas 节点列表、知识标签、Run、回放按钮、事件列表与 Inspector；提供可见焦点、正确的按钮标签、Esc 关闭浮层和明确的状态文本。
- 正文对比度参考至少 4.5:1，重要状态不能仅通过颜色区分；不把长文本压缩到 3D 贴图中。
- 完成实际测试并记录 FPS/主要交互响应等观察，不允许杜撰“保证所有设备 60fps”。
