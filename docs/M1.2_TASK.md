## 2. 内容计划：前三章、18 个概念

**必须保留 M1.1 和 M0.3 已存在的稳定概念 ID；若实际仓库不同，以实际 ID 为准，保留兼容别名，不做破坏性迁移。**

| 章节 | 概念 ID（建议） | 必须解释的问题 |
|---|---|---|
| 01 Intelligence | `ai`, `ml`, `llm`, `transformer`, `token`, `inference` | AI/ML/LLM 的范围；Transformer 的作用；Token 是什么；模型输出与事实核验之间的区别 |
| 02 Context | `prompt`, `instructions`, `system_prompt`, `context_window`, `context_engineering`, `hallucination` | 提示词和指令、上下文、窗口、预算、错误陈述之间的关系 |
| 03 Connection | `api`, `tools`, `tool_calling`, `function_calling`, `mcp`, `mcp_server` | 模型与工具执行的分工、API 与 Tool Calling 的区别、MCP 的 Host/Client/Server 与能力类型 |

每个概念至少包括：**一句话解释**、`UNDERSTAND`（零基础讲解）、`INSPECT`（准确技术细节与边界）、本章研究情境示例、≥1 常见误解及纠正、语义关系、相关实验入口、经核实参考资料（名称/组织/可访问链接/核验时间或版本）。不能伪造文献；无法核实的内容标记为待审，不得作为“已发布/已掌握”内容。正文面向中文新手，关键英文术语保留并解释。

### 必须明确区分的概念

- LLM 不是 Agent；对话中描述工具操作不等于真正调用工具。
- Token 不等于字符、汉字或自然语言单词；不同 tokenizer 会导致不同结果。**切勿用固定字符数假称真实 Token 数。**
- `context window` 约束能纳入的上下文规模，具体计数规则与模型/接口相关；示意预算不是某个真实模型的承诺。
- `system prompt` 与其他指令的优先级行为依具体实现而异；不要夸大为绝对安全边界。
- “幻觉”不等于一切不确定性；输出是否真实必须与来源核查区分。
- Tool Calling 是模型/应用选择或描述工具调用的机制；工具实际执行与授权由运行环境负责；Function Calling 常是此类机制的一种 API 表达，避免虚构普适唯一标准。
- MCP 是连接协议；不是 Agent、工具、联网能力的同义词。MCP Server 可暴露 Tools、Resources 和 Prompts；与平台内置工具调用不是一回事。
- “用户连接某协议”不应在模拟里自动提高研究结论的准确度。

## 3. 三章 Story 主线与交互过渡

始终使用 M0.4 已有的**虚构校园活动整合研究**资料包；不把虚构公告混入真实技术参考资料。

### Chapter 01 / MODEL WITHOUT EVIDENCE

开场研究任务：“请判断整合分散的校园活动公告是否可行。”先展示一个**显式标注为模拟**、看似流畅却没有引用依据的回答。用户进入 Token 实验，理解模型处理输入和生成输出的基本方式。章节结束显示局限：“能生成回答，并不等于已经检索、阅读和核验了资料。”自然引出上下文与任务要求。

### Chapter 02 / DEFINE THE QUESTION

用户发现研究目标不够明确，通过预设指令卡、背景资料选择、模拟上下文预算调整，观察报告结构和限制说明发生变化。章节结尾：“指令更清晰，但没有接入真实资料，仍无法核实公告。”自然引出工具。

### Chapter 03 / CONNECT TO THE WORLD

通过已存在的 Search/Reader 演示调用外部资料的流程；对比直接工具链路与 MCP Host/Client/Server 演示路径。结束时展示：“工具可以带来可检查的资料，但返回数据不自动保证正确”，衔接后续 Chapter 04（检索/知识）和 Chapter 06（可靠性）。

每章必须提供：章节开场目标、至少一次可观察的问题/局限、清楚的实验入口、结果解读、上一章/下一章导航、随时退出到 Atlas；不强制锁关。章节动画沿用 AZ 视觉语言，不因每个概念重复长运镜。

## 4. Lab 01 · TOKEN / CONTEXT BUDGET

### 功能

1. 提供 3–5 句中文、英文及混合文本样例，可点击切换；若支持自定义输入，必须保证计数源可靠，否则应明确标示“自定义文本仅作可视化估算”。
2. **优选**离线打包可运行的 tokenizer，并明确其对应编码/模型族；如体积或适配不可接受，使用**预计算且已验证**的样例 Token 序列，不对任意输入伪称真实计数。
3. 可视化原文、Token 片段与边界、序号、数量、示意上下文预算；允许改变预算上限以演示超出预算时的情形。
4. 展示“系统指令 / 用户任务 / 已选文档片段 / 保留给输出的预算”在示例窗口中的占用关系。演示预算不等于实际模型接口中所有隐式 Token 的真实计数。
5. 支持重置与状态解说；如发生超限，明确告诉用户哪项材料被示意性截断/舍弃及依据。

### 验收底线

对于预计算样例，同一编码与文本必须得到同一组 Token；切换语言/文本会更新分块和预算；关闭 JS 动画也能读取结果；无 API 依赖。

## 5. Lab 02 · INSTRUCTIONS / CONTEXT

### 可配置内容

- 研究目标：宽泛任务 / 明确研究问题。
- 输出方式：自由陈述 / 结构化研究提纲。
- 证据要求：无明确要求 / 标注来源及不确定性。
- 背景资料：不添加 / 添加虚构校园活动背景卡片。
- 上下文预算：充足 / 受限（受限场景中部分背景无法使用）。

### 模拟逻辑

- 使用**确定性的规则表或纯函数**根据配置生成结构化结果，绝不能随机播放固定“更聪明”的答案。
- 结果包括：实际接收的上下文、报告段落结构、来源状态、被遗漏内容、变化原因。
- 缺乏来源时必须输出“未验证”，不得因为勾选“要求引用”就制造虚构引文。
- 如果用户减少预算，显示具体被舍弃的背景条目，以及为什么。
- 可对比两次配置变化（本章可做轻量前后对照，**不是** M2 的完整 A/B Agent 实验室）。

## 6. Lab 03 · TOOL CALLING / MCP

必须**复用既有 M0.3 Tool Calling Lab、M0.2 Search/Reader 配置和 M0.4 研究数据**，不得旁路模拟引擎伪造第二套执行记录。

### 模式 A：直接工具调用（教学模式）

输入研究任务 → 模拟模型选择工具/生成结构化工具请求 → 环境校验工具与权限 → 本地工具执行 → 返回响应 → 模拟模型处理结果。用户可暂停、单步、展开请求参数和响应数据。

### 模式 B：MCP 连接路径演示

用户在同一工具能力上切换“直连示意 / MCP 适配示意”；显示 Host、Client、Server、能力发现/选择、请求/响应的角色关系，展示 Tools、Resources、Prompts 三种能力的区别。**协议路径作为可视化教学仿真，不声称实现真实 MCP 握手或 SDK。**

### 必须满足

- 工具未装配/未启用/无权限时，不能显示调用成功。
- Search 可发现资料，Reader 才能查看正文；二者独立，源于仓库真实的模拟规则。
- 允许选择成功/超时预设情境；失败后显示异常事件和对应原因，不强行完成研究。
- MCP 与直连模式在同样能力和数据条件下，不能凭“用了 MCP”改变文档事实和研究质量。
- 用户点击 Knowledge Node 的相关入口可聚焦正确的工具、协议角色或时间轴事件。
